# Модель угроз Anki-decks

Документ описывает границы доверия, точки входа, активы и нарушителей набора
инструментов репозитория. Его используют ревью безопасности и сканирование кода,
чтобы оценивать находки по фактическому устройству системы. Утверждения о коде
сверяй с текущим состоянием файлов: при расхождении источник истины — код.

## Обзор системы

Это локальный однопользовательский набор инструментов на Rust (рабочая
область Cargo, `tools/*`) и агентские процессы для CrowdAnki JSON-колод.
Развёрнутого сервера нет. Инструменты работают на машине владельца (Linux или
WSL), обращаются к Anki Desktop через AnkiConnect на loopback, управляют
Chromium/Brave по CDP для сбора словарных данных и произношения, при
необходимости выполняют модель на собственном локальном сервере либо
обращаются к внешнему HTTP-сервису. CI работает в GitHub Actions и может
исполняться на собственном раннере владельца. Колоды, медиа и приватный журнал
лежат в игнорируемых Git областях (`decks/**`, `.asset-store/`) и не
публикуются. Отдельного инфраструктурного репозитория нет.

## Компоненты

| Компонент | Код | Назначение |
| --- | --- | --- |
| **Инструменты `anki-repo`** | `tools/anki-repo/src`, кроме `desktop/` | Разбор `deck.json`, QA, `edit`/`create`/`retire`/`migrate-media`/`migrate-layout` (изменения по умолчанию не записываются и требуют `--apply`), HTML-отчёт `visual-report` (пишется в указанный через `--out` каталог), работа с путями (`paths.rs`, `layout.rs`, `media.rs`), санитайзер превью (`htmlscan.rs`). |
| **Связь с Anki Desktop** | `tools/anki-repo/src/desktop/` | Клиент AnkiConnect (`transport.rs`, `http://127.0.0.1:8765`, без прокси и перенаправлений), установка и патч дополнений AnkiConnect и CrowdAnki (`patch.rs`; `bootstrap.py` исполняет `payload.py` внутри Anki), задания. |
| **Хранилище ресурсов** | `tools/asset-store/src`: хранилище, журнал, пакеты, конвейеры кандзи, высотного ударения и произношения, `review_ui.rs`, `temp_workspace.rs` | Общее хранилище медиа, жизненный цикл, журнал, интерфейс проверки, временные рабочие каталоги. |
| **Получение веб-данных** | `tools/asset-store/src/browser_runtime*`, `browser_process.rs`, `jpdb.rs`, `yarxi.rs`, `forvo*`, `pronunciation*` | Chromium через `chromiumoxide` по CDP; сбор данных с jpdb.io, yarxi, forvo.com (Forvo — через авторизованный профиль Brave), загрузка изображений и аудио. |
| **Выполнение моделей** | `tools/asset-store/src/inference*.rs`, `llama_server.rs`, `kanji_ocr.rs`, `pitch_llm_review.rs` | Собственный управляемый `llama-server` работает на loopback; внешний `llama-server` или Ollama могут обслуживаться на loopback либо по явно разрешённому удалённому HTTP-адресу. Запросы могут содержать промпты и изображения; вывод модели влияет на решения проверки. Ollama-модель, которую API отмечает как исполняемую удалённо (`remote_host`), отклоняется. SHA-256 локального файла и сообщённый Ollama digest служат для идентификации модели и повторного использования результатов, но не подтверждают её доверенное происхождение. |
| **Обслуживание** | `tools/repository-maintenance` | Таймер `systemd --user`, запускающий `anki-repository-maintenance clean --apply`: удаление кэшей и артефактов. |
| **Инструменты разработки** | `tools/anki-e2e`, `tools/benchmark-*`, `benchmarks/` | E2E-стенд в Docker, стенд Real-Site с Brave, исполнитель и история бенчмарков (запуск Hyperfine, данные XDG); запускаются по явному запросу. |
| **Непрерывная интеграция (CI)** | `.github/workflows`, `.github/scripts`, `renovate.json` | `ci.yml` на `pull_request`/`push`/расписании/`workflow_dispatch` с `permissions: contents: read`, возможный собственный раннер владельца `home-wsl-x64`; `pr-body-trusted.yml` на `pull_request_target` имеет `contents: read`; `codeql.yml` дополнительно имеет `security-events: write` для публикации результатов CodeQL, но не права записи в содержимое репозитория. `fetch_verified_tool.py` скачивает закреплённые инструменты с проверкой SHA-256. |

## Границы доверия и точки входа

1. **Собранный веб-контент → получение веб-данных и хранилище ресурсов.** HTML,
   JSON, изображения и аудио с jpdb.io, yarxi, forvo.com, kanjivg, kakijun и
   других источников могут попасть в файлы, поля колод и HTML-отчёты. Их
   контролирует тот, кто владеет или скомпрометировал сайт. Сетевой атакующий
   может влиять на содержимое там, где соединение не защищено TLS или действует
   принятое исключение Yarxi: оно включено по умолчанию и позволяет продолжить
   переход через предупреждение сертификата для указанного ниже узла.
2. **CrowdAnki JSON и медиа → инструменты `anki-repo`, связь с Anki Desktop.**
   Экспорты, в том числе чужие колоды: имена в `media_files`, HTML полей,
   шаблоны и CSS моделей.
3. **Сервисы на loopback.** AnkiConnect (8765), локальный `llama-server`/Ollama,
   порт отладки CDP, VNC/noVNC и тестовые серверы E2E. Доступны любому локальному
   процессу или пользователю; при ошибочной привязке — локальной сети. Страницы
   браузера могут достучаться до них через DNS rebinding или CSRF.
4. **Явно разрешённый удалённый сервер модели.** Адрес внешнего
   `llama-server` или Ollama вне литерального loopback требует `allow_remote = true`
   либо `--allow-remote`. Адреса принимаются только по HTTP, поэтому запросы с
   изображением и промптом не шифруются и доступны оператору сервера и
   наблюдателю сетевого пути. Это разрешение относится к адресу сервиса:
   облачная модель Ollama, отмеченная `remote_host`, всё равно отклоняется.
5. **Процесс Anki Desktop.** Патч дополнения исполняет Python внутри Anki с
   доступом к коллекции пользователя.
6. **Вывод модели → решения проверки.** Текст модели недоверенный.
7. **CI.** Код PR, включая PR из форков, выполняется на машинах GitHub;
   собственный раннер владельца используется только по правилу выбора
   исполнителя ниже. Отдельно работает workflow на `pull_request_target`.
8. **Цепочка поставок.** Зависимости Cargo (`deny.toml`, Renovate), закреплённые
   actions, скачиваемые инструменты CI, браузеры, дополнения AnkiWeb и веса моделей.

## Активы

Все активы равноценны:

- машина владельца: нет исполнения чужого кода, записи или удаления вне
  предназначенных каталогов (символические ссылки, обход пути, `clean --apply`);
- целостность локальных колод, медиа и приватного журнала;
- коллекция Anki Desktop и установленные дополнения;
- собственный раннер `home-wsl-x64` (это WSL на машине владельца);
- авторизованные сессии браузера и учётные данные (профиль Brave с входом на
  Forvo, cookie-файлы).

## Нарушители

Все перечисленные нарушители реалистичны:

- вредоносный или скомпрометированный сайт-источник (jpdb, yarxi, forvo) либо
  сетевой атакующий, в том числе наблюдающий незашифрованный HTTP-трафик к
  удалённому серверу модели;
- оператор внешнего сервера модели, которому отправляются изображения и промпты;
- автор колоды или медиа, которые владелец импортирует;
- внешний участник, открывающий PR (PR из форков в CI);
- другие локальные процессы или пользователи машины (порты loopback, общие
  временные каталоги);
- атакующий цепочку поставок (зависимости, скачиваемые инструменты, модели,
  дополнения).

## Существующие меры защиты

- `unsafe_code = "forbid"` в крейтах. Команды изменения CrowdAnki-экспорта
  (`edit`, `create`, `retire`, `migrate-media`, `migrate-layout`) по умолчанию
  работают в предварительном режиме без записи и требуют `--apply`;
  `visual-report --out` записывает отдельный отчёт. Команды `kanji-assets`
  создают или меняют собственное хранилище по своим контрактам (например,
  `init`, `ingest`, `ensure`); общего
  требования `--apply` для них нет. `anki-repo maintenance enable/disable`
  настраивают пользовательский таймер по явной команде.
- Клиент AnkiConnect: `no_proxy`, без перенаправлений, тайм-аут, проверка URL
  сервиса (запрет учётных данных, пути и `query`), проверка сетевого режима WSL.
- Проверки путей в патче Desktop (`check_ancestors`, только обычные файлы,
  `safe_path`/`media_name` в `payload.py`), сверка SHA-256 изменяемых файлов.
- Временные рабочие каталоги и профили браузера создаются приватными; порты
  Docker привязаны к 127.0.0.1, привязка проверяется.
- Санитайзер превью и экранирование атрибутов в `visual-report`.
- Выбор исполнителя CI (`runs-on` в `ci.yml`): собственный раннер — только если
  инициатор и запустивший — владелец репозитория и это либо `workflow_dispatch`
  с `runner=local`, либо PR владельца из этого же репозитория (с учётом
  `CI_RUNNER_MODE` и `CI_AUTO_LOCAL_UNTIL`); PR из форков идут на `ubuntu-latest`.
- Права токена задаются отдельно для каждого сценария CI: `ci.yml` и
  `pr-body-trusted.yml` имеют `contents: read`; `codeql.yml` имеет права чтения
  `contents`, `actions` и `packages`, а также `security-events: write` для
  публикации результатов CodeQL. Прав `contents: write` у CodeQL нет. Действия
  GitHub Actions закреплены SHA, в доверенной проверке описания PR задано `persist-credentials:
  false`, инструменты скачиваются с проверкой SHA-256; используются CodeQL,
  cargo-deny и Renovate.
- Для Yarxi TLS-исключение включено по умолчанию, но допускает только переход
  по ссылке со страницы предупреждения Chrome на HTTPS-адрес верхнего уровня с
  точным узлом `www.yarxi.su`, портом 443 и без учётных данных, если код ошибки
  — `ERR_CERT_AUTHORITY_INVALID`. Глобальный `--ignore-certificate-errors` и
  отключение проверки TLS не используются; `--allow-insecure-tls=false`
  запрещает исключение. Если его принять, сетевой атакующий может подменить
  содержимое Yarxi.
- Для удалённого вывода модели адрес вне loopback требует явного
  `allow_remote = true` или `--allow-remote`, но соединение остаётся HTTP без
  шифрования. Идентичность весов фиксируется хешем локального файла или digest,
  сообщённым Ollama. Если для внешнего `llama-server` путь к модели не задан,
  записывается только сообщённый сервером путь (`reported-path`); API не
  сообщает отдельный projector, поэтому он помечается `unverified:external`.
  Эти сведения помогают сопоставлять модель и решать, можно ли повторно
  использовать результат, но не проверяют доверенное происхождение весов,
  подпись или соответствие заранее доверенному эталону.

## Вне области и принятые риски

Ничего не исключено: отказ в обслуживании, инструменты разработки и атаки
со стороны других локальных пользователей остаются в области.

## Открытые вопросы

- Привязываются ли сервисы loopback к внешним интерфейсам (mirrored-режим WSL,
  Docker)?
- Импортируются ли чужие колоды через этот набор инструментов или только через
  Anki?
