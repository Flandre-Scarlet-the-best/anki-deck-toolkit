# Модель угроз Anki-decks

Документ описывает границы доверия, точки входа, активы и нарушителей набора
инструментов репозитория. Его используют ревью безопасности и сканирование кода,
чтобы оценивать находки по фактическому устройству системы. Утверждения о коде
сверяй с текущим состоянием файлов: при расхождении источник истины — код.

## Обзор системы

Это локальный однопользовательский набор инструментов на Rust (рабочая
область Cargo, `tools/*`) и агентские процессы для CrowdAnki JSON-колод.
Развёрнутого сервера нет. Инструменты работают на машине владельца (Linux или
WSL), обращаются к Anki Desktop через AnkiConnect на loopback, управляют
Chromium/Brave по CDP для сбора словарных данных и произношения, при
необходимости выполняют локальный LLM-вывод. CI работает в GitHub Actions и
может исполняться на self-hosted раннере владельца. Колоды, медиа и приватный
журнал лежат в игнорируемых Git областях (`decks/**`, `.asset-store/`) и не
публикуются. Отдельного инфраструктурного репозитория нет.

## Компоненты

| Компонент | Код | Назначение |
| --- | --- | --- |
| **Deck CLI** | `tools/anki-repo/src`, кроме `desktop/` | Разбор `deck.json`, QA, `edit`/`create`/`retire`/`migrate-media`/`migrate-layout` (запись только по `--apply`), HTML-отчёт `visual-report`, работа с путями (`paths.rs`, `layout.rs`, `media.rs`), санитайзер превью (`htmlscan.rs`). |
| **Desktop bridge** | `tools/anki-repo/src/desktop/` | Клиент AnkiConnect (`transport.rs`, `http://127.0.0.1:8765`, без прокси и редиректов), установка и патч дополнений AnkiConnect и CrowdAnki (`patch.rs`; `bootstrap.py` исполняет `payload.py` внутри Anki), задания. |
| **Asset store** | `tools/asset-store/src`: хранилище, журнал, пакеты, конвейеры кандзи, высотного ударения и произношения, `review_ui.rs`, `temp_workspace.rs` | Общее хранилище медиа, жизненный цикл, журнал, интерфейс проверки, временные рабочие каталоги. |

| **Local inference** | `tools/asset-store/src/inference*.rs`, `llama_server.rs`, `kanji_ocr.rs`, `pitch_llm_review.rs` | Собственный или внешний `llama-server` либо Ollama на loopback; веса закреплены SHA-256 или digest; вывод модели влияет на решения проверки. |

## Границы доверия и точки входа

1. **Собранный веб-контент → Web acquisition, Asset store.** HTML, JSON,
   изображения и аудио с jpdb.io, yarxi, forvo.com, kanjivg, kakijun и других
   источников. Доступны тому, кто контролирует или скомпрометировал сайт либо
   сетевой путь. Попадают в файлы, поля колод и HTML-отчёты.
2. **CrowdAnki JSON и медиа → Deck CLI, Desktop bridge.** Экспорты, в том числе
   чужие колоды: имена в `media_files`, HTML полей, шаблоны и CSS моделей.
3. **Сервисы на loopback.** AnkiConnect (8765), `llama-server`/Ollama, порт
   отладки CDP, VNC/noVNC и fixture-серверы E2E. Доступны любому локальному
   процессу или пользователю, при ошибочной привязке — локальной сети; страницы
   браузера могут достучаться до них через DNS rebinding или CSRF.
4. **Процесс Anki Desktop.** Патч дополнения исполняет Python внутри Anki с
   доступом к коллекции пользователя.
5. **Вывод LLM → решения проверки.** Текст модели недоверенный.
6. **CI.** PR, включая PR из форков, исполняют код head на GitHub-hosted
   раннерах; self-hosted раннер — только по правилу выбора исполнителя ниже.
   Отдельно — workflow на `pull_request_target`.
7. **Цепочка поставок.** Зависимости Cargo (`deny.toml`, Renovate), закреплённые
   actions, скачиваемые инструменты CI, браузеры, дополнения AnkiWeb, веса моделей.

## Активы

Все активы равноценны:

- машина владельца: нет исполнения чужого кода, записи или удаления вне
  предназначенных каталогов (symlink, path traversal, `clean --apply`);
- целостность локальных колод, медиа и приватного журнала;
- коллекция Anki Desktop и установленные дополнения;
- self-hosted раннер `home-wsl-x64` (это WSL на машине владельца);
- авторизованные сессии браузера и учётные данные (профиль Brave с входом на
  Forvo, cookies).

## Нарушители

Все перечисленные нарушители реалистичны:

- вредоносный или скомпрометированный сайт-источник (jpdb, yarxi, forvo) либо
  сетевой атакующий;
- автор колоды или медиа, которые владелец импортирует;
- внешний участник, открывающий PR (PR из форков в CI);
- другие локальные процессы или пользователи машины (порты loopback, общие
  временные каталоги);
- атакующий цепочку поставок (зависимости, скачиваемые инструменты, модели,
  дополнения).

## Существующие меры защиты

- `unsafe_code = "forbid"` в крейтах; запись только по `--apply`; diff в режиме
  без записи.
- Клиент AnkiConnect: `no_proxy`, без редиректов, тайм-аут, проверка endpoint
  (запрет учётных данных, пути и query), проверка сетевого режима WSL.
- Проверки путей в патче Desktop (`check_ancestors`, только обычные файлы,
  `safe_path`/`media_name` в `payload.py`), сверка SHA-256 изменяемых файлов.
- Временные рабочие каталоги и профили браузера создаются приватными; порты
  Docker привязаны к 127.0.0.1, привязка проверяется.
- Санитайзер превью и экранирование атрибутов в `visual-report`.
- Выбор исполнителя CI (`runs-on` в `ci.yml`): self-hosted раннер — только если
  инициатор и запустивший — владелец репозитория и это либо `workflow_dispatch`
  с `runner=local`, либо PR владельца из этого же репозитория (с учётом
  `CI_RUNNER_MODE` и `CI_AUTO_LOCAL_UNTIL`); PR из форков идут на `ubuntu-latest`.
- CI: токен только на чтение, actions закреплены SHA, `persist-credentials:
  false` в доверенной проверке описания PR, скачивание инструментов с проверкой
  SHA-256, CodeQL, cargo-deny, Renovate.
- Веса моделей закреплены SHA-256 или digest Ollama.

## Вне области и принятые риски

Ничего не исключено: отказ в обслуживании, инструменты разработки и атаки
со стороны других локальных пользователей остаются в области.
