# Ручной шаг Forvo

1. Запусти production CLI асинхронно с раздельными stdout и stderr. Исполнитель
   должен отдавать строки stderr до выхода процесса и сохранять владение
   процессом/браузером между обращениями агента. Если это невозможно,
   сообщи ограничение клиента; не называй синхронный запуск событийным.
2. На NDJSON `human_interaction_required` немедленно вызови штатный
   интерактивный инструмент запроса ответа в текущем клиенте. Передай варианты
   «Проверку прошёл», «Не получилось», «Зависло / нужна диагностика» и фактический
   `timeout_seconds`. В режиме `resume_required` команда уже завершает попытку,
   срока активного ожидания нет: дождись ответа перед штатным повтором.
   Не повторяй вопрос по тому же `session_id`.
3. Пока ответ не получен, приостанови генерацию. Чтение потоков и наблюдение
   процесса выполняет исполнитель без LLM. При поддержке только асинхронного
   вопроса заверши агентский ход с сохранением работающего процесса и
   событийного наблюдателя. Не запускай периодические модельные проверки,
   не ставь внешний короткий timeout и не обещай бессрочное ожидание:
   автоматическое восстановление CDP ограничено 300 секундами; `login`
   сообщает выбранный `--timeout-seconds`.
4. «Проверку прошёл»: CLI сам подтверждает авторизацию на странице. CDP
   продолжает ту же сессию и исходную операцию; агент не записывает признак входа.
   Расширение возвращает `challenge_required`/`next_action`: после ручного шага
   повтори предусмотренную команду или `batch-resume`, не управляй чужой вкладкой.
5. «Не получилось»: передай штатное прерывание принадлежащему процессу,
   дождись итогового JSON и очистки. Для расширения не начинай новую загрузку.
   «Зависло / нужна диагностика»: сначала проверь процесс, события и состояние
   собственного окна; не перезапускай операцию и не убивай её только из-за тишины.
6. `human_interaction_finished` сообщает `authenticated`, `timed_out`,
   `interrupted` или `failed`. Истечение срока — обнаружимый отказ с
   `human_wait=timed_out`; stdout остаётся одним итоговым JSON. При гонке
   с внешним штатным сигналом итог содержит `interrupted`, а событие завершения
   ручного шага фиксирует прерывание. `SIGINT`, `SIGTERM`, `SIGHUP` направляются
   только своему CLI и ведут через очистку. Повторное принудительное прерывание
   и `SIGKILL` могут не оставить JSON: проверь сохранённые checkpoint/recovery
   markers и продолжай штатным способом.
7. При ошибке cleanup используй `details.source.batch_id`, `acquisition`,
   `recovery_required` и `next_action`. Отмена не списывает долг очистки:
   `batch-resume` отменённого пакета с recovery выполняет только очистку.

Если штатного интерактивного инструмента нет, явно скажи это и используй
обычный диалог. Не утверждай, что ожидание без расхода токенов реализовано,
если клиент вынужден постоянно перезапускать модель. Не записывай пароль,
cookies, токены и содержимое личного профиля в события и отчёт.
