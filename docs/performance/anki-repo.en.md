Performance of the short CrowdAnki export analysis commands
([command contract](../../tools/anki-repo/README.en.md)): the last confirmed
snapshot per catalog scenario. The general measurement rules are in the
[methodology](README.en.md), scenario fields in the
[benchmark catalog](benchmarks.en.md).

## What is measured

- `anki-repo.validate` — `anki-repo --json validate` on one export: reading and
  parsing `deck.json`, resolving models, structural checks.
- `anki-repo.stats` — `anki-repo --json stats`: typed loading and aggregation
  over the deck tree.

The measured interval is the built release binary from process start to exit;
the build, warmups and computing the export identity are outside it. Metrics:
`time_wall_clock` (required), `time_cpu`, `memory_peak_resident` and
`instructions` (without `perf_event` access — `unavailable` with a reason).

## Workload

The export is passed as the `export_dir` parameter and does not appear in the
result: the workload is represented by the tree content identity and size
(`deck_json_bytes`, `notes`, `media_files`). User decks never go into the public
snapshot: the snapshot's reference workload is a synthetic export without media,
and its size is stated in the block. Only results with the same workload
identity and size can be compared.

## How to measure

```bash
cargo run -p benchmark-runner -- check anki-repo.validate --profile warm --param export_dir=/path/to/export
cargo run -p benchmark-runner -- run anki-repo.validate --profile warm --param export_dir=/path/to/export --runs 20
cargo run -p benchmark-history -- list --scenario anki-repo.validate
cargo run -p benchmark-history -- snapshot <ID> --page docs/performance/anki-repo.md
```
