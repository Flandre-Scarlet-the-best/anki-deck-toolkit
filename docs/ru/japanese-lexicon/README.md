# Japanese Lexicon: `japanese-lexicon`

`japanese-lexicon` — самостоятельная японская лексическая подсистема. Она
ставит и обновляет локальные словари в формате Yomitan и офлайн отвечает
на вопрос: «какие чтения допустимы у этого написания и на основании какого
словаря?».

Подсистема не принадлежит Forvo, ASR, `anki-repo` или какой-то колоде и не
читает их данные: `decks/**`, `media/`, `.asset-store/`, профили браузеров,
Anki и приватную базу расширения Yomitan. Словари не хранятся в Git: их
скачивает и индексирует сам пользователь в локальный каталог данных.

**Ни один результат словаря не является акустической проверкой.** Чтение из
словаря — кандидат для последующего сопоставления с аудио, а не
доказательство, что в конкретном MP3 произнесён именно этот вариант.

## Быстрый старт

```bash
cargo build -p japanese-lexicon --release
B=target/release/japanese-lexicon

$B install --all                 # скачать, проверить и проиндексировать стандартный набор
$B status                        # что установлено, версии, число записей, пути
$B lookup --surface 今日         # чтения с происхождением (офлайн)
$B check-updates --all           # есть ли новые версии (ничего не меняет)
$B update --all                  # получить и активировать новые версии
$B verify                        # локальная проверка целостности (alias: doctor)
$B remove jmnedict               # удалить один словарь (alias: uninstall)
$B install jmnedict              # вернуть его
$B remove --all                  # удалить всё (спросит подтверждение)
```

Глобальные флаги: `--data-dir DIR` — каталог данных, `--json` — стабильный
машинный вывод вместо текста. Текстовый вывод показывает строки словаря
(заголовок, ревизию, названия помет, чтения) без управляющих символов и
перестановок направления: они печатаются escape-последовательностью вида
`\u{001B}`, чтобы подготовленный ZIP не управлял терминалом. `--json` передаёт
исходные значения без изменений.

Ошибку разбора аргументов формирует сам `clap` до входа в приложение, поэтому
она даётся русским текстом (`ошибка аргументов: …`, строка использования и
подсказка о справке) в stderr с кодом возврата `2`, а имена флагов, команд и
машинных значений остаются без перевода. При `--json` такая ошибка **не**
становится JSON: машинный контракт `japanese-lexicon.error/1` со стабильным
`code` остаётся у доменных отказов и не расширяется. `--help`/`-h` и
`--version`/`-V` печатаются в stdout с кодом `0`.

## Стандартный набор

| ID | Назначение | Upstream и обнаружение версии | Контрольная сумма |
|---|---|---|---|
| `jitendex` | `lexicon` — основные написания и чтения (на основе JMdict), английские определения | последний опубликованный релиз GitHub `stephenmk/stephenmk.github.io`, ассет `jitendex-yomitan.zip` (на него ведёт официальная страница [jitendex.org](https://jitendex.org/pages/downloads.html)) | SHA-256 ассета, опубликованная GitHub (`digest`); `revision` в `index.json` обязана совпасть с тегом релиза |
| `jmnedict` | `proper_names` — имена людей, мест, организаций | последний релиз `yomidevs/jmdict-yomitan`, ассет `JMnedict.zip` | SHA-256 ассета (`digest`) |
| `kanjidic-english` | `kanji` — он/кун-чтения и сведения об отдельных знаках | последний релиз `yomidevs/jmdict-yomitan`, ассет `KANJIDIC_english.zip` | SHA-256 ассета (`digest`) |
| `jpdb-v2.2-freq-kana` | `frequency` — частотность, только аннотация | файл `dictionaries/JPDB_v2.2_Frequency_Kana_YYYY-MM-DD.zip` ветки `main` репозитория `Kuuuube/yomitan-dictionaries` с самой поздней датой (его рекомендует README репозитория) | git blob SHA-1, опубликованная GitHub для файла; считается с обнаружением коллизий (SHA-1DC, как в Git), архив с признаками атаки коллизией отклоняется с `checksum_mismatch` |

Версия, имя файла, ссылка и опубликованная сумма каждый раз берутся из
живого ответа GitHub API, а не из кода. Старые релизы
`Jitendex/Jitendex` не используются: этот репозиторий сам отсылает за
файлами на jitendex.org. Вариант JPDB зафиксирован точно — v2.2 Frequency
Kana; файлы `…_Display_Only_…`, `JPDB_v2.2_Frequency_…` без `Kana` и
другие версии JPDB не подставляются. Если discovery источника сломался,
команда честно сообщает отказ и не переключается на зеркало, другой словарь
или старый релиз.

Обычный английский JMdict не ставится параллельно: Jitendex уже основан на
нём, и он не был бы независимым вторым свидетелем.

## Лицензии и атрибуция

Данные словарей — не собственность проекта; `status` показывает лицензию и
атрибуцию каждого источника.

- **Jitendex** — CC BY-SA 4.0, © Stephen Kraus; включает JMdict © EDRDG и
  примеры Tatoeba (CC BY 2.0 FR).
- **JMnedict, KANJIDIC2** — [EDRDG General Dictionary Licence](https://www.edrdg.org/edrdg/licence.html)
  (CC BY-SA 4.0); для KANJIDIC действуют особые условия отдельных полей
  (например, SKIP) — см. страницу лицензии.
- **JPDB v2.2 Frequency Kana** — код репозитория `Kuuuube/yomitan-dictionaries`
  под MIT; отдельная лицензия частотных данных jpdb.io не указана. Поэтому
  данные только скачиваются локально и никуда не распространяются.

Репозиторий не содержит и не публикует ни словарных ZIP, ни индексов:
тесты используют маленькие синтетические архивы с собственными статьями.

## Где лежат данные

| Источник | Путь |
|---|---|
| `--data-dir DIR` | `DIR` |
| `JAPANESE_LEXICON_DIR` | значение переменной |
| `XDG_DATA_HOME` | `$XDG_DATA_HOME/anki-deck-toolkit/japanese-lexicon` |
| иначе | `~/.local/share/anki-deck-toolkit/japanese-lexicon` |

Путь должен быть абсолютным и без `..`. Изменяющие операции отвергают
каталог внутри рабочей копии Git до создания файлов; команды чтения
(`status`, `verify`, `lookup`, `check-updates`) расположение относительно Git
не проверяют и сами каталог не создают. Непустой каталог без маркера `owner.json`
подсистема себе не присваивает (`not_owned`).

Управляемые промежуточные каталоги — `staging/`, `dictionaries/` и
`dictionaries/<id>/` — обязаны быть настоящими каталогами. Если на их месте
символическая ссылка или файл, `install`, `update`, `remove`, `status` и
`verify` отказывают с `not_owned` до любой записи или удаления (`lookup` и
`check-updates` только читают реестр и активные версии): очистка остатков, перенос версии и
удаление словаря не проходят через ссылку и не затрагивают её цель. Сам
каталог данных (`--data-dir`) ссылкой быть может. Ссылка на месте отдельного
остатка (каталога версии или staging) удаляется как ссылка, её цель не
обходится. Защита рассчитана на случайные и устаревшие ссылки, а не на
параллельного злоумышленника с правами того же пользователя: между проверкой
и действием раскладку можно подменить.

```text
<каталог>/
├── owner.json                         # маркер принадлежности
├── registry.json                      # активная версия каждого словаря
├── operations.lock, active.lock       # блокировки (создаются только изменяющими командами)
├── dictionaries/<id>/<версия>/
│   ├── archive.zip                    # проверенный исходный архив (SHA-256 в манифесте)
│   ├── index.sqlite                   # нормализованный индекс
│   └── manifest.json                  # происхождение, хеши, статистика
└── staging/                           # незавершённые загрузки и сборки
```

Объём на сегодня: Jitendex ≈ 110 МБ, JMnedict ≈ 125 МБ, JPDB ≈ 60 МБ,
KANJIDIC ≈ 4 МБ (архив + индекс).

## Поиск чтений: `lookup --surface`

Поиск полностью офлайн и идёт по **точному** написанию после NFC (NFKC не
применяется). Ключи индекса строятся из написаний словаря той же
нормализацией NFC, поэтому канонически эквивалентные записи (составной и
разложенный дакутэн, совместимый и основной иероглиф) находят друг друга, а
полуширинная и полноширинная кана — нет. Исходное написание словаря и ссылка
`bank`/`row` в свидетельстве остаются без изменений. Пробелы, управляющие символы и строки длиннее 64 символов
отвергаются (`invalid_input`).

### Классы свидетельств

| Класс | Откуда | Что значит |
|---|---|---|
| `lexical_entry` | `jitendex` | пара написание/чтение из лексической статьи |
| `surface_kana` | само написание | для записи каной чтение выводится фонетически |
| `proper_name` | `jmnedict` | вариант имени собственного; не смешивается с лексикой |
| `kanji_reference` | `kanjidic-english` | он/кун-чтение **символа**, не подтверждённое самостоятельное слово |

Частотность JPDB только аннотирует найденные чтения (`frequency` у группы;
`kana_writing: true` — пометка JPDB `㋕` «частота записи каной») и никогда не
создаёт чтение. Частотность для чтения, которого нет в словарях, уходит в
`frequency_unmatched`.

Указатели Jitendex (`redirects`) — статьи вида «старая форма 勞働 → 労働» —
показываются отдельно: это ссылка на другую форму с её чтением, а не чтение
запрошенного написания.

### Статусы

| `status` | Когда |
|---|---|
| `single_reading` | ровно одно различное чтение классов `lexical_entry`/`surface_kana` |
| `multiple_readings` | несколько таких чтений; выбор требует контекста (`今日`, `明日`, `一日`) |
| `kanji_reference_only` | одиночный кандзи без лексической статьи: только чтения символа |
| `kanji_reference_and_proper_name_only` | одиночный кандзи без лексической статьи, у которого есть и чтения символа, и варианты имён собственных (`間`) |
| `proper_name_only` | только варианты имён собственных |
| `redirect_only` | только указатель на другую форму |
| `ambiguous` | запись каной с сомнительными знаками: чтение не выводится уверенно |
| `source_missing` | лексических чтений нет, потому что Jitendex не установлен или недоступен |
| `not_found` | нужные словари есть, но написания в них нет |

Статус не выбирает «правильное» чтение по частотности или score: порядок
групп — класс, предпочтение словаря, score статьи и нормализованное
чтение — только порядок показа. `distinct_readings` перечисляет все
различные чтения независимо от пагинации. `complete: false` и
`missing_sources` показывают, каких относящихся к запросу словарей не было.
Словарь, отказавший во время поиска (например, повреждённый индекс),
помечается `unavailable` в `sources`; его свидетельства в ответ не попадают, а
поиск продолжается по исправным словарям.

### Кана

Поддерживаются хирагана, катакана, `ー` (не в начале) и `・`. Нормализованная
форма — хирагана (катакана сдвигается кодово), `ー`, малые знаки и `っ`
сохраняются; `・` опускается. Полуширинная катакана, знаки повтора
(`ゝゞヽヾ`), отдельные знаки дакутэна и редкие буквы (`ヷ…`) дают `ambiguous`
с диагностикой в `kana.issues`. Вывод чтения из каны не зависит от
словарей и работает даже без них.

### Одиночный кандзи

Лексические чтения (`lexical_entry`) и чтения символа (`kanji_reference`)
различаются. Для кун-чтения KANJIDIC вида `い.きる` в свидетельстве есть
`character_reading: "い"` и `okurigana: "きる"`; пометы `なま-`/`-う` дают
`affix: prefix`/`suffix`, а помета с дефисами с обеих сторон (`-ま-`) — `infix`.

### Объём ответа

`--limit` (50 групп), `--offset` (0) и `--max-evidence` (10 свидетельств в
группе) ограничивают вывод; `truncation` сообщает, сколько групп всего и
сколько свидетельств скрыто. Текстовый вывод подсказывает `--offset`/`--limit`
только тогда, когда за выборкой остались ещё группы, а скрытые свидетельства
показывает с подсказкой `--max-evidence`. `--limit` и `--max-evidence` (поля
`limit` и `max_evidence` библиотечного `Options`) должны быть не меньше 1: ноль
отвергается как `invalid_input` и молча не заменяется. Вывод детерминирован.

### Библиотечный API

```rust
let lexicon = japanese_lexicon::lookup::Lexicon::open(&root)?;
// По умолчанию ответ ограничен 50 группами и 10 свидетельствами на группу.
let all = japanese_lexicon::lookup::Options {
    offset: 0,
    limit: usize::MAX,
    max_evidence: usize::MAX,
};
let result = lexicon.lookup("今日", &all)?;
for target in result.candidate_targets() {
    // target.surface, target.reading (нормализованная хирагана),
    // target.classes (lexical_entry / surface_kana), target.dictionaries
}
```

`candidate_targets()` возвращает пары `surface + reading` только из классов
`lexical_entry` и `surface_kana` — кандидатов для будущего адресного
сопоставления с аудио. Имена собственные и чтения символа в кандидаты не
попадают; интегратор может взять их из `readings` явно. Кандидаты строятся из
показанной страницы `readings`, поэтому ненулевой `offset` или малый `limit`
дают только её часть, а `max_evidence` сокращает и список `dictionaries`. Для
полного набора вызывайте `lookup` без пагинации либо опирайтесь на
`distinct_readings`, который от страницы не зависит.

## Управление словарями

| Команда | Что делает | Сеть | Пишет данные |
|---|---|---|---|
| `status` (`list`) | весь набор: установлен ли, версия, записи, путь, лицензия и атрибуция; быстрая проверка размеров файлов | нет | нет |
| `install --all` / `install <id>…` | ставит недостающие словари; установленный словарь с читаемым манифестом — `already_installed` без обращения к сети | да | да |
| `install <id> --from-file ZIP` | ручной импорт локального Yomitan ZIP — установка без источника публикации; установленный словарь не заменяет, запись с нечитаемым манифестом заменяет | нет | да |
| `check-updates --all` / `<id>…` | сравнивает установленный архив с опубликованной суммой источника публикации | да | **нет** |
| `update --all` / `<id>…` | скачивает и активирует только изменившиеся словари; неустановленные пропускает | да | да |
| `remove <id>…` (`uninstall`) | удаляет словарь из каталога подсистемы | нет | да |
| `remove --all` | удаляет все словари; в терминале спрашивает `yes`, без терминала требует `--yes` | нет | да |
| `verify [<id>…]` (`doctor`) | SHA-256 архива и индекса против манифеста, `quick_check` SQLite, счётчики, реестр | нет | **нет** |
| `lookup --surface …` | поиск чтений | нет | нет |

### Исходы по словарю

`installed`, `already_installed`, `updated`, `up_to_date`,
`update_available`, `not_installed`, `unknown`, `check_failed`, `failed`,
`removed`. Команды с `--all` возвращают исход **каждого** словаря; общий
итог `ok: false` при любом `failed`/`check_failed`.

- `up_to_date` ставится только при совпадении опубликованной суммы с
  установленным архивом. Совпадение тега, размера или ETag таковым не
  считается.
- `already_installed` — в реестре есть запись словаря и её манифест читается:
  `install` такую версию не заменяет, даже если её индекс или архив повреждён.
  Запись с нечитаемым манифестом установленной не считается: `install` (в том
  числе с `--from-file`) активирует версию заново, а `update` переустанавливает
  её; прежний каталог версии при активации удаляется.
- `unknown` — источник публикации не опубликовал сумму, новизну можно установить только
  скачиванием (`update` сравнит SHA-256 и не перестроит индекс напрасно).
- `check_failed` — сеть, лимит GitHub или ответ не позволили проверить; это
  никогда не выдаётся за «обновлений нет».
- Словарь, установленный из локального файла, сравнивается с источником публикации по
  контрольной сумме так же.

### Как устроены установка и обновление

Этапы разделены: обнаружение версии → скачивание с проверкой размера и
опубликованной суммы → проверка архива → построение индекса → манифест и
fsync → перенос из `staging` → атомарная замена `registry.json`. Новая
версия не видна до последнего шага. Отказ на любом этапе (сеть, 404,
неверная сумма, битый ZIP, несовместимая схема, небезопасный путь, нехватка
места, обрыв индексирования) оставляет прежнюю активную версию нетронутой;
незавершённый `staging` удаляется. Если процесс был убит, остаток уберёт
следующая `install`/`update`/`remove` (поле `cleaned` отчёта); `verify`
показывает такие остатки, но ничего не удаляет.

`update` глубоко проверяет активную версию: повреждённый индекс или архив
того же релиза переустанавливается, а не считается актуальным. Смена схемы
корпуса тоже ведёт к перестроению.

### Проверка архива

ZIP Yomitan — формат импорта, а не доказательство доверия. Архив никогда
не распаковывается на диск: банки читаются в память по одному с
ограничением фактически прочитанных байт. Отвергаются: абсолютные пути,
`..`, `\`, `:`, управляющие символы, повторяющиеся имена, символические
ссылки, шифрование, неизвестное сжатие, записи больше 256 МиБ, суммарно
больше 3 ГиБ, больше 20 000 записей, коэффициент сжатия выше 1000 (zip bomb),
несовпадение заявленного и фактического размера `index.json` и банков (только
они читаются; медиа и сопроводительные файлы проверяются по заявленному
размеру и не распаковываются), неизвестный тип банка,
банки, не ожидаемые для этого словаря, файлы, которые не являются
`index.json`, банком, медиа или сопроводительным текстом (`LICENSE`),
`format` ≠ 3 и `title` чужого словаря. Скачивание идёт только по HTTPS к
хостам GitHub (`api.github.com`, `github.com`,
`objects.githubusercontent.com`, `release-assets.githubusercontent.com`,
`raw.githubusercontent.com`) с не более чем пятью редиректами в их пределах.

### Конкурентный доступ

Изменяющие операции (`install`, `update`, `remove`) исключают друг друга
через `operations.lock`; вторая получает `busy` (код возврата 4) после
короткого повтора, чтобы мгновенная проба `status`/`verify` не давала ложный
отказ. Сами `status`/`verify` определяют выполняющуюся операцию без записи
и создания файлов.
Команды чтения (`status`, `verify`, `lookup`, `check-updates`) ничего не
создают и не меняют в каталоге данных, в том числе файлы замков: их создаёт
первая изменяющая операция. Реестр и активные версии они читают под
разделяемой блокировкой `active.lock`; если её файла ещё нет, чтение идёт без
блокировки и повторяется под ней, если замок появился за время чтения.
Поиск берёт разделяемую блокировку только на время чтения реестра и
открытия индексов, а индексы открывает как неизменяемые файлы: удаление или
замена версии во время запроса не ломает уже открытый поиск, а следующий
запрос видит новую версию.

## Сохранённые данные для будущих английских значений

Импорт ничего не выбрасывает. `index.sqlite` (схема корпуса `3`, поле
`corpus.schema` манифеста) хранит каждую строку банка терминов с исходными
полями Yomitan (`term`, `reading`, `definition_tags`, `rules`, `score`,
`sequence`, `term_tags`), классом записи (`entry`, `redirect`,
`reading_list`, `no_reading`) и ссылкой `bank`/`row` на исходную строку.
Глоссарий — английские значения, части речи, формы, пометы, ссылки,
атрибуция Jitendex — остаётся в проверенном `archive.zip` рядом и
адресуется этой ссылкой, а не дублируется в индексе. Значения KANJIDIC
хранятся в индексе как JSON. Русский словарь и русские определения не
создаются; переводчики и LLM в поиск и установку не подключены.

`score` статьи схема банка терминов Yomitan объявляет как `number` (не
`integer`) и использует его как оценку частотности для сортировки
результатов, поэтому оценка хранится числом с плавающей точкой без
усечения до целого; в машинном ответе целое значение остаётся целым
(`200`), дробное печатается дробным. `sequence` и другие целочисленные поля
по-прежнему ожидают целое: строка, логическое значение и дробное число
отклоняются как `invalid_format`, а целое, записанное как `1.0`, и `null` допустимы.

Правила разбора, зависящие от источника:

- **Jitendex**: пустое чтение допустимо только у записи каной (тогда чтение
  совпадает с написанием); статья с `redirect-glossary` — указатель; статья
  с кандзи без чтения сохраняется как `no_reading` и чтений не даёт. Теги
  разделяются только ASCII-пробелом: `old kanji form` содержит неразрывные
  пробелы и является одним тегом.
- **JMnedict** (yomitan-import): при пустом чтении глоссарий — список чтений
  этого написания каной (`origin: glossary_reading_list`); при непустом —
  переводы.

## Коды

Коды отказов в JSON (`code`): `unknown_dictionary`, `not_installed`,
`invalid_format`, `unsupported_schema`, `unsafe_archive`, `limit_exceeded`,
`checksum_mismatch`, `index_corrupt`, `upstream_unavailable`,
`upstream_unexpected`, `upstream_rate_limited`, `busy`, `not_owned`,
`confirmation_required`, `invalid_input`, `io`.

Коды возврата: `0` — успешно; `1` — команда выполнена, но не для всех
словарей успешно или `verify` нашёл проблемы; `2` — неверный вызов или нет
подтверждения; `3` — ошибка; `4` — выполняется другая изменяющая операция.

## Диагностика

| Симптом | Что делать |
|---|---|
| `check_failed` / `upstream_unavailable` | нет сети или GitHub недоступен; повторите позже. Поиск продолжает работать по установленному |
| `upstream_rate_limited` | GitHub API ограничил запросы: основной лимит (анонимно 60 в час; `x-ratelimit-remaining: 0`) — повторите после сброса окна; вторичный лимит (`403`/`429` с `retry-after` или сообщением о secondary rate limit) — подождите не меньше минуты. Обычный `403` без этих признаков — `upstream_unexpected` |
| `upstream_unexpected` | источник публикации изменил релиз или структуру; данные не тронуты. Сообщите о проблеме; как временную меру можно скачать ZIP вручную и выполнить `install <id> --from-file` |
| `checksum_mismatch` | полученные байты не совпали с опубликованной суммой; повторите `update` |
| `verify` показывает `index_corrupt` | выполните `update <id>`: повреждённая версия переустановится. Без сети: `install <id> --from-file ZIP`, а если манифест читается и `install` отвечает `already_installed` — сначала `remove <id>` |
| `busy` | дождитесь завершения другой операции |
| `not_owned` | укажите пустой или новый каталог вне рабочей копии Git; при «небезопасной структуре» замените символическую ссылку `staging`/`dictionaries` настоящим каталогом |
| `lookup` → `source_missing` | поставьте Jitendex: `install jitendex` |

## Проверки

Тесты `cargo test -p japanese-lexicon` строят синтетические Yomitan-архивы
и поддельный источник публикации с теми же формами ответов GitHub; реальные словари и
сеть в тестах не используются. Живую установку с настоящего источника публикации
выполняет пользователь вручную в выделенном каталоге (`--data-dir`); в CI
она не запускается.
