# Forvo через обычный браузер: адаптер-расширение

`pronunciation-assets forvo browser` работает с Brave, Google Chrome, Microsoft Edge и
Vivaldi; прежний `forvo brave` закреплён только за целью `brave`. Обе команды обращаются
к Forvo через обычный авторизованный браузер пользователя — без отдельного профиля,
`--remote-debugging-port`, Browser MCP и экспорта cookies. Отдельный профиль Cloudflare отклонял (`403`, `cf-mitigated: challenge`);
основной профиль пользователя проходит. Через браузер работают одиночное получение с
импортом в `AssetStore` (`fetch`) и пакеты (`batch-start|batch-resume`) поверх того же
`forvo::batch`/`SafeBatchRuntime`, что у [CDP-провайдера](forvo.md). `doctor` и `smoke`
остаются диагностикой транспорта и одной записи.

Браузеры различаются только обнаружением, развёртыванием, подсказками и проверкой
возможностей. Расширение, bridge, выбор записи, загрузка MP3, `ForvoEvidence` и пакеты
у всех одни; копий Forvo-кода по браузерам нет.

## Браузеры и цели

**Цель** — одно независимое сопряжение с одной установкой браузера: свой каталог
распакованного расширения (а значит, свой ID), свой секрет, свой порт bridge и свой
закреплённый экземпляр расширения. Все цели лежат в одном приватном файле `state.json`
в каталоге состояния (`schema_version=2`). Имя цели по умолчанию — имя браузера
(`brave`, `chrome`, `edge`, `vivaldi`); для второго профиля того же браузера
настройте отдельную цель (`--target chrome-work`).

- **Обнаружение** (`forvo browser discover`) подтверждает разновидность по самому
  исполняемому файлу, а не по имени каталога: у Windows-браузеров из WSL — по
  `ProductName` и `FileVersion` ресурса версии PE, у Linux-браузеров — по выводу
  `--version`. Весь запуск `--version`, включая чтение вывода, ограничен 10 с;
  потомок обёртки, унаследовавший stdout, не продлевает ожидание и завершается вместе
  с группой процесса, а вывод больше 64 КиБ не принимается. Каталог без исполняемого
  файла или файл с чужим продуктом установкой не считается. Версия, которую нельзя прочитать надёжно, выводится как `null`. У
  Vivaldi своя нумерация, поэтому версия Chromium для него до подключения неизвестна.
  Нестандартный путь задаётся `--executable` (путь Windows `C:\…\chrome.exe` в WSL или
  Linux-путь). Cookies, история и профили браузера не читаются.
- **Выбор однозначен.** `forvo browser` без `--target` использует цель по умолчанию
  (`select`) или единственную настроенную. При нескольких целях без выбора — отказ
  `target_ambiguous` со списком. При нескольких найденных браузерах `setup` без
  `--browser` отказывает `browser_ambiguous`, при нескольких установках одного
  браузера — `installation_ambiguous`. «Первое ответившее» расширение не выбирается
  никогда.
- **`forvo brave` — совместимый способ работы с целью `brave`.** Он не зависит от цели
  по умолчанию и не переключается на другой браузер.
- **Цели не делят сопряжение.** `setup` отказывает, если каталог (`install_dir_conflict`)
  или порт (`port_conflict`) уже принадлежат другой цели. Каталоги сравниваются
  физически: символьная ссылка, ссылка на родительский каталог, `..` или иной регистр
  несуществующей части пути у браузера Windows из WSL — тот же каталог. Проверка
  выполняется до записи файлов расширения; тем же критерием проверяется загруженное
  и записываемое `state.json`. Сохранённые `install_dir` и `load_unpacked_path` при
  этом не канонизируются: от строки пути зависит ID расширения. Если путь нельзя
  проверить (например, нет доступа к его части), `setup` отказывает с
  `install_dir_unverifiable`. Порт новой цели выбирается свободным, начиная с 47613.

### Что подтверждено

Разновидность браузера и возможности его API ещё не означают, что Forvo работает.
Ниже — что проверено фактически, а что нет; при расхождении источник истины —
`doctor` и `smoke` на конкретной установке.

| Браузер | Изолированный E2E (временный профиль, fixture) | Живой Forvo в профиле пользователя |
|---|---|---|
| Brave | весь набор | подтверждён на Windows из WSL2 `mirrored`: миграция v1, автообновление расширения, `doctor`, `fetch`, пакет с возобновлением |
| Chromium / Chrome for Testing | весь набор | не применимо (тестовые сборки) |
| Google Chrome | весь набор (Linux; расширение загружается через CDP pipe только во временном профиле) | не проверен |
| Microsoft Edge | весь набор; запрос места сохранения распознаётся как `save_as_suspected` | `doctor` подтверждён в отдельном временном профиле Windows, загрузка с Forvo не проверялась |
| Vivaldi | Проходят сценарии без CDP-навигации вкладки пользователя. `BLOCKED`: `extension_bridge_tab`, `concurrent_downloads`, `browser_restart`, `cli_fetch`, `cli_batch_recovery`, `cli_foreign_downloads` — Vivaldi не завершает навигацию вкладки с подключённым CDP-клиентом стенда (сам адаптер CDP не использует). Нужна настройка «Начинать загрузки автоматически», без неё — `BLOCKED download_not_started` с действием | не проверен; `setup` выводит предупреждение `support_note` |

- WSL2 в режиме NAT не проверен: подключение зависит от localhost forwarding, `doctor`
  показывает режим и безопасные варианты.
- `browser_identity` для Vivaldi всегда `NOT_TESTED`: по брендам он неотличим от Chrome.
- Настройка «Спрашивать, куда сохранять» не читается заранее (`download_settings`
  остаётся `NOT_TESTED`) и проявляется только при загрузке.

## Первый запуск, обновление и переход к другому браузеру

```bash
pronunciation-assets forvo browser discover                    # что установлено (без изменений)
pronunciation-assets forvo browser setup --browser chrome      # каталог расширения и сопряжение
pronunciation-assets forvo browser --target chrome doctor      # подключение и проверка браузера
```

1. **Первый запуск.** `setup` выводит `user_action` с точной страницей и путём, например:
   «Откройте `chrome://extensions` в Google Chrome, включите „Режим разработчика“,
   нажмите „Загрузить распакованное“ и выберите `C:\Users\…\AnkiDeckToolkit\forvo-chrome-adapter`».
   Для Edge — `edge://extensions`, для Vivaldi — `vivaldi://extensions`, для Brave —
   `brave://extensions`. Это единственное ручное действие. Программа не ставит
   расширение сама: в личный Chrome, Edge и Vivaldi распакованное расширение
   устанавливается только через режим разработчика. Enterprise policy, реестр Windows,
   права администратора, CDP пользовательского профиля и обход интерфейса установки не
   используются. Обычный Google Chrome 137+ игнорирует `--load-extension`, поэтому этот
   флаг пользовательским способом не является. «Установлено» не сообщается, пока
   расширение не подключилось и не прошло проверку ID и секрета.
2. **Обновление встроенной версией.** Повторный `setup` идемпотентен: секрет, ID,
   каталог, порт и закрепления сохраняются, отличающиеся файлы заменяются одной
   транзакцией (см. [обновление из выпусков](#обновление-из-выпусков)). Если в каталоге
   уже стоит более новая версия из проверенного выпуска, `setup` и автоматическая
   синхронизация её не откатывают: меняется только `pairing.json` при ротации секрета.
   Повреждённый `state.json` даёт отказ `state_corrupt`, а не новую «чистую» настройку.
   Если порт цели занят — идёт `fetch` или пакет этой цели, — `setup` отказывает
   `adapter_busy` и файлов не трогает. Ручная перезагрузка не нужна. Любая команда цели
   (`doctor`, `smoke`, `fetch`, пакет), заняв порт bridge, приводит файлы установленного
   расширения к версии CLI, если установленная версия старее встроенной. Если подключилось
   расширение не той версии, что лежит в каталоге цели, она штатно
   перезагружает **своё** расширение (`chrome.runtime.reload`) и проверяет новую версию.
   При незавершённой собственной загрузке перезагрузка откладывается
   (`deferred_operation_pending`): операция освобождается обычным восстановлением, а
   обновление выполняется при следующей команде. Браузер не перезапускается, его
   настройки не меняются.
3. **Другой браузер.** `setup --browser edge` добавляет цель `edge`, не трогая прежние.
   `select --target edge` делает её целью по умолчанию для `forvo browser`. Пакет
   продолжается только своей браузерной сессией (см. ниже).
4. **Переустановка расширения.** После «Удалить» и повторной «Загрузить распакованное»
   у расширения новый экземпляр, и bridge его отвергает (`instance_mismatch`).
   Выполните `setup --repin`: секрет и каталог прежние, закрепление снимается и
   восстанавливается при следующем подключении. `--rotate-secret` создаёт новый
   секрет; расширение подхватит его после перезагрузки.

Старое состояние единственного Brave (`schema_version=1`) читается как цель `brave` с
прежними секретом, ID, каталогом и портом. Первая запись переводит его в версию 2, а
исходный файл сохраняется рядом как `state.v1.json` (0600). Повторная установка
расширения не нужна.

## Архитектура

- MV3-расширение (`tools/asset-store/src/forvo/brave/extension/`) — тонкий транспорт.
  Оно подключается WebSocket-клиентом к локальному bridge `ws://127.0.0.1:47613/forvo-adapter/v1`
  и выполняет фиксированный набор команд: `ping`, `tab_status`, `open`, `navigate`,
  `auth`, `dom`, `download_begin`, `download_status`, `download_release`,
  `downloads_api`, `download_cleanup`, `snapshot`, `close`, `reload`. Произвольного
  кода, `eval`, `debugger`, `cookies`, `tabs`, `webRequestBlocking` и
  `declarativeNetRequest` нет. Права: `https://forvo.com/*` и `http://127.0.0.1/*`;
  `webRequest` используется только для неблокирующего наблюдения (см. ниже).
- Разметку страницы читают те же `forvo/dom.js` и `forvo/auth.js`, что и CDP-провайдер.
  Пакет адаптера (`forvo/brave/package.rs`) собирает из них `forvo_page.js`; тот же
  набор файлов разворачивает `setup` и упаковывает релизный ZIP, второй реализации
  DOM-логики нет.
- Rust принимает все решения: навигацию, проверку входа, рейтинг и выбор кандидата
  (`Candidate::validate`, `rank`), проверку адреса загрузки (`matches_download`),
  SHA-256 и `probe_mp3`.

## Сопряжение и безопасность

`setup` создаёт для цели 32-байтный секрет и записывает его в файл `pairing.json` в
каталоге расширения и в приватный файл `state.json` (0600) в каталоге состояния
(`$XDG_CONFIG_HOME/anki-deck-toolkit/forvo-brave/`, `--state-dir`; имя каталога
историческое). Единственный акт доверия — установка расширения из каталога цели. Bridge:

- слушает только `127.0.0.1` (не `0.0.0.0`); `doctor` проверяет недоступность порта
  по нелокальным адресам (список из `ip -j addr`, а без iproute2 — из `/proc/net/fib_trie`);
- до upgrade проверяет путь, `Host` и `Origin: chrome-extension://<id>`. ID
  распакованного расширения Chromium вычисляется из пути его каталога (SHA-256 пути,
  в Windows — UTF-16LE). До первого сопряжения принимается только ID каталога цели, так
  что расширение, загруженное из другого каталога, отвергается
  (`extension_id_mismatch`). После первого сопряжения ID закрепляется;
- проводит взаимную проверку HMAC-SHA256 по одноразовым nonce: расширение не
  исполняет команды bridge, не знающего секрета, а bridge отвергает клиента без секрета
  (`pairing_mismatch`);
- закрепляет **экземпляр** расширения. Расширение версии 0.3+ хранит случайный ID в
  `chrome.storage.local` своего профиля и сообщает его в `ready` после взаимной
  проверки. Тот же каталог, загруженный во второй профиль, даёт тот же ID расширения и
  секрет, но другой экземпляр, и отвергается (`instance_mismatch`). Экземпляр
  закрепляется при первом подключении версии 0.3+. Ограничение: если расширение одного
  каталога в этот момент уже загружено в два профиля, закрепится первый подключившийся
  экземпляр. Остальные будут отвергаться, а `doctor` покажет число отказов;
- ограничивает размер сообщений и принимает только известные типы и операции.

Причины отказов подключений учитываются. Если расширение так и не подключилось,
код ошибки называет причину (`pairing_mismatch`, `extension_id_mismatch`,
`instance_mismatch`, иначе `extension_not_connected`), а `user_action` — точное
действие для браузера цели.

Секрет, cookies, HTML и заголовки не попадают в stdout, журналы и отчёты. Bridge
не делает исходящих HTTP-запросов, поэтому `HTTP_PROXY`/`HTTPS_PROXY` в WSL на него
не влияют. Chromium не проксирует `127.0.0.1`.

## Вкладка и жизненный цикл

Расширение создаёт одну неактивную вкладку в свёрнутой группе `Anki Deck Toolkit`
и запоминает её ID. Chromium разрешает вкладке без жеста пользователя только первую
загрузку (`DownloadRequestLimiter`): вторая блокируется молча или вызывает панель
«Скачать несколько файлов». Поэтому вкладка, уже начавшая загрузку, при следующем
`open`/`navigate` заменяется свежей в той же группе, а `download_begin` на ней
отвечает `own_tab_used`. Настройки браузера не меняются. После `chrome.runtime.onStartup` (перезапуска браузера) состояние
сбрасывается, чтобы не «усыновить» чужую вкладку с тем же ID. Если пользователь закрыл
вкладку, следующая команда создаёт новую. Пользовательские вкладки не читаются: снимок
изоляции содержит только ID, окна, группы и порядок.

Новая вкладка считается готовой, только когда браузер зафиксировал её адрес на
`https://forvo.com`. Vivaldi сначала фиксирует начальную `about:blank` и на миг отдаёт
вкладку как загруженную без адреса. Такую вкладку нельзя доказуемо признать своей, и
следующая команда открыла бы вторую. Если навигация собственной вкладки потерялась, она
повторяется один раз, иначе — `tab_group_failed`. Сразу после запуска браузера окно может
быть ещё не размечено: интерфейс Vivaldi сам является веб-страницей, и вкладка,
созданная раньше разметки, навсегда остаётся с нулевым viewport. Поэтому перед созданием
вкладки расширение ждёт до 3 с, пока у активной вкладки окна появится размер.


Идентичность собственной вкладки хранится в `chrome.storage.session`: она переживает
перезапуск service worker, но сбрасывается при перезапуске браузера или расширения.
Восстановленная группа с новыми ID не доказывает владения, даже если её заголовок,
URL и состояние совпадают с группой адаптера. Такие группы сохраняются; следующая
команда создаёт отдельную собственную вкладку. Сомнительную старую группу пользователь
может закрыть вручную.

Перед каждой командой диагностика повторяется. `ping.restored_cleanup` содержит
`groups_closed`/`tabs_closed` (ноль при недоказанном владении), `groups_kept`,
`ownership_unproven` и `status` (`complete`, `ownership_unproven` или `error`).
Ошибка запроса групп не выдаётся за завершённую очистку и допускает повтор.
`close` удаляет только собственную вкладку текущей сессии; отказ удаления сохраняет
идентичность для повторной попытки. Своей считается только группа с сохранённым ID
этой сессии: одноимённая группа другой цели того же профиля или восстановленная группа
не закрывается и не мешает закрытию, а учитывается в `unproven_groups_kept`.

Создание и замена вкладки — одна операция владения. Новая вкладка сразу записывается
в `chrome.storage.session` как остаток и становится собственной только после
группировки; заменённая вкладка остаётся остатком до подтверждённого удаления. Если
шаг создания не удался, вкладка удаляется (`tab_group_failed`). Если не удалось и
удаление, отказ не скрывается: команда получает `tab_cleanup_failed`, вкладка остаётся
в списке остатков, а следующие `open`/`close` (в том числе после перезапуска service
worker) повторяют удаление и до его успеха новых вкладок не создают. Остаток, который
пользователь уводит с forvo.com (по `url` или по `pendingUrl` ещё не завершённой
навигации), считается его вкладкой и забывается без закрытия.

Гарантия повторной очистки ограничена. Если не удалось сохранить в
`chrome.storage.session` даже запись об остатке, расширение сразу пытается удалить
вкладку. Если не удалось и это, команда получает `tab_cleanup_failed`
(`leftover_not_recorded`), но ID вкладки нигде не сохранён: повторная команда её не
найдёт и не закроет, а по URL или названию группы адаптер чужие и свои вкладки не
различает. Такую вкладку пользователь закрывает вручную. Кроме того, между проверкой
адреса остатка и его удалением пользователь может начать навигацию: этот промежуток
API браузера атомарно не закрывает.

Активную повторно используемую вкладку `doctor` и `smoke` не считают ошибкой: её мог
открыть сам пользователь, например проходя проверку сайта. Новая вкладка обязана быть
неактивной.

Service worker держит соединение keepalive-сообщениями каждые 20 секунд. После
разрыва он делает 5 быстрых попыток, дальше подключается по `chrome.alarms` раз
в 30 секунд. Поэтому первое подключение после простоя может занять до 30 секунд.
Ctrl+C, отключение и перезапуск bridge закрывают только соединение: Brave,
вкладки и настройки загрузок не меняются.

## Загрузка MP3: одна штатная загрузка и доказанное владение

Пользователь выключил в Brave «Спрашивать, куда сохранять каждый файл», поэтому
обычная кнопка Forvo сохраняет файл в стандартную папку загрузок без диалога.
Адаптер не меняет эту настройку и не предполагает её у других пользователей.

Путь получения — **одна** загрузка: без отмены, без повторного HTTP-запроса и без
`onDeterminingFilename`.

1. Rust выбирает запись и создаёт идентификатор операции (`operation_id`, 32 hex).
   `download_begin` проверяет страницу и то, что загрузка того же адреса уже не идёт.
   Затем сохраняет операцию в `chrome.storage.local`, включает наблюдатель и нажимает
   обычную кнопку выбранной строки.
2. Перед кликом расширение добавляет случайный маркер операции в query собственной
   страницы через `history.replaceState`, без перезагрузки и без изменения адреса MP3.
   У `DownloadItem` нет `tabId`: источником доказательства служит **точный referrer**
   этой уникальной страницы, а не совпадение URL/времени/байтов. Если политика
   referrer скрыла query, загрузка не усыновляется. Неблокирующий `webRequest`
   дополнительно подтверждает один запрос своей вкладки и обнаруживает конкуренцию
   той же записи, в том числе после связывания. Недавняя запись истории без маркера
   своей не считается. Rust требует явного `ownership_proven` и точного referrer.
3. Rust опрашивает `download_status` и решает по фактам (`download::classify`).
   Таймеры service worker не считаются гарантией. Файл читается только у `complete`
   с согласованными `bytesReceived`/`totalBytes`/`fileSize`, не `.crdownload`, обычный
   файл без symlink. Далее идут длина, SHA-256 и `probe_mp3`; байты сохраняются без
   конвертации, автоматического `Verified` нет. Windows-путь Brave в WSL переводится
   через `wslpath`, Linux-путь используется как есть.
4. `download_release` с `remove` удаляет файл и запись истории только у **связанной**
   загрузки после копии в свидетельства. Незавершённую загрузку оно отменяет,
   а `--keep-download` оставляет файл. Несвязанная операция ничего не трогает.

Неоднозначность останавливает только собственную операцию (fail closed):

| Код | Когда | Что с файлами |
|---|---|---|
| `download_conflict` | загрузка той же записи из другой вкладки до связывания или уже идущая до клика | ничего не трогается |
| `ownership_unproven` | рестарт service worker до связывания, совпадение без запроса своей вкладки | ничего не трогается |
| `download_not_started` | ответ не стал загрузкой, адрес не совпал или браузер заблокировал загрузку | посторонние загрузки не трогаются. У Vivaldi так выглядит выключенное «Начинать загрузки автоматически»: окно подтверждения расширению не видно, поэтому итог — `BLOCKED` с действием включить настройку на `vivaldi://settings/downloads`. Окно подтверждения закрывает пользователь |
| `save_as_required` | связанная загрузка без имени файла дольше 8 с или окно выбора закрыто без сохранения | собственная отменяется и стирается; итог `BLOCKED` с инструкцией выключить настройку. Уже показанное окно сохранения Chromium после отмены не закрывает, его закрывает пользователь. В новом профиле Brave для Linux запрос места включён по умолчанию |
| `save_as_suspected` | связанная загрузка уже получила имя и все байты, но браузер держит её в `in_progress` дольше общего таймаута — так ведёт себя Edge, ожидая выбора в окне сохранения | собственная отменяется и стирается; итог `BLOCKED` с той же инструкцией выключить «Спрашивать, куда сохранять» на странице загрузок браузера цели. Код означает подозрение, а не доказанный диалог |
| `download_interrupted` / `download_canceled` / `download_dangerous` / `download_timeout` | состояние `DownloadItem` | собственная стирается |
| `own_tab_closed`, `download_mismatch`, `file_missing`, `file_access_denied`, `download_incomplete`, `download_invalid`, `probe_failed` | соответствующая проверка | только связанная собственная |

Расширение не отменяет, не переименовывает, не перенаправляет и не удаляет загрузки
пользователя, в том числе другие записи Forvo в других вкладках. Задержки после
операции нет. Наблюдатель `webRequest` существует только во время операции.
`doctor` и `smoke` проверяют через `hasListeners()`, что после операции нет ни
`onDeterminingFilename`, ни наблюдателя запросов.

Ctrl+C даёт работе до 20 секунд освободить собственную операцию: отменить незавершённую
загрузку или удалить непроверенный файл. Повторный Ctrl+C закрывает только
соединение. Если процесс завершился без освобождения, следующий `smoke` находит
операцию в `ping` и освобождает её по тем же правилам: несвязанную — без
изменений файлов. Разрыв bridge во время загрузки не теряет операцию: Rust ждёт
переподключения и продолжает опрос. Рестарт service worker после связывания
продолжает операцию, до связывания — завершает её как `ownership_unproven`.

`download_release` подтверждает `canceled`, `removed_file` и `erased` только после
успеха соответствующего API. Ошибка отмены/удаления не стирает историю и состояние
операции; ошибка `erase` сохраняет подтверждение удаления файла для повтора.
Очистка и события наблюдателя проходят через одну очередь, поэтому отложенное
событие не воскрешает освобождённую операцию. `download_cleanup` получает FAIL
при неподтверждённой очистке; `keep` и отсутствие операции допустимы без удаления.
После обновления старое состояние без маркера не принимается и не удаляется:
для связанной операции прежней версии потребуется ручная проверка файла/истории
и освобождение через `keep`.

Управляемые регрессии границы Chrome API (с реальными временными файлами):
`node --test tools/asset-store/tests/brave_extension_test.cjs`. Они проверяют
порядок событий и отказы API, но не заменяют браузерный набор.

`smoke --probe-downloads-api` — отдельный эксперимент приёмки. Он повторно скачивает
адрес уже связанной собственной загрузки через `chrome.downloads.download({saveAs:false})`
в `AnkiDeckToolkit/` и сравнивает SHA. Владение здесь доказывает ID, который вернул API.
В рабочем пути вторая загрузка не нужна.

## Получение и пакеты

`forvo brave fetch` и пакеты Brave выдают тот же результат получения, что CDP:
`Acquisition { bytes, evidence }` с единым `ForvoEvidence`. Сессия Brave
(`forvo::brave::fetch::BraveSession`) реализует общий `CandidateSource`, поэтому
действует один `acquire_from`:
- рейтинг кандидатов;
- переход к следующему кандидату при допустимом отказе;
- попытки и сведения о происхождении;
- проверка MP3 (`probe_mp3` — один раз, в общем порядке попыток);
- импорт через `import_acquisition`.

Происхождение аудио для обоих путей одно: `provider=forvo_web`, `source_kind=forvo_web`.
Транспорт — отдельное свойство пакета, а не источник. Техническая проверка не даёт
фонетического доверия: ресурс остаётся `Uncertain`/карантином до человеческого одобрения.

Одна команда (`fetch`) или один исполнитель пакета держит одно логическое сопряжение с
расширением на всё выполнение. `doctor`/`smoke` и новый bridge на каждое слово не
запускаются. При подключении освобождается операция, оставшаяся от прерванного
запуска (`brave_operation_recovery`): затрагивается только связанная собственная загрузка.
Каждое слово открывается в свежей собственной вкладке. Вкладка, уже нажавшая кнопку
загрузки, заменяется расширением. Перед нажатием строка выбранного кандидата проверяется
заново. Если строка изменилась или пропала, это `candidate_changed`: перебор
останавливается, а пакет приостанавливается, как в CDP. После каждой загрузки собственная операция освобождается при любом
исходе: незавершённая собственная загрузка отменяется, а завершённая — удаляется из
загрузок и истории после чтения байтов. Этот путь не создаёт копий в `evidence/` и отчётов `smoke`, не делает второй
HTTP-запрос и `chrome.downloads.download` ради перепроверки.
Если разрыв WebSocket случился между командами (перезапуск service worker), команда
ждёт переподключения и повторяется один раз. Во время загрузки разрыв обрабатывается
опросом операции, как в `smoke`.

Отказ одной записи — не блокер. К следующему кандидату ведут только отказы самой
записи, общие с CDP: не-MP3 (`invalid_mp3`), обрыв (`download_aborted`), неверный адрес
(`download_mismatch`), неполный или неверный файл (`download_incomplete`,
`download_invalid`) и недоступная кнопка записи. Остальные коды, включая
`candidate_changed` и неизвестные, останавливают перебор с исходным кодом. Если подходящих кандидатов не
осталось, слово получает отдельный исход `candidates_exhausted`, `word_not_found` или
`japanese_pronunciation_not_found`. Блокирующие состояния останавливают перебор, а пакет
переводят в `paused`. Это:
- вход и проверка сайта: `login_required`, `challenge_required`;
- недоступность расширения: `extension_not_connected`;
- запрос места сохранения: `save_as_required` или `save_as_suspected`;
- неоднозначное владение: `download_conflict`, `ownership_unproven`;
- недоступность проверки MP3: `technical_validation_failed`.

Слово при блокере не объявляется безнадёжным. Подсказка `next_action` указывает
действие в браузере цели (для `save_as_required` — его страницу настроек загрузок).
После входа или прохождения проверки вручную выполните `batch-resume` той же цели.

Транспорт пакета закреплён в состоянии. Новые пакеты CDP имеют `schema_version=2` и
`transport=cdp_chromium`. Новые пакеты расширения имеют `schema_version=4`,
`transport=brave_extension` (имя историческое, транспорт один для всех браузеров) и
сразу сохраняют разрешённую цель в `target`. После успешного подключения поле `browser`
дополняется привязкой цели, браузера, ID расширения и экземпляра; она дальше не меняется.
`forvo browser batch-resume` без `--target` использует сохранённую цель либо привязку.
Resume другой целью отвергается до подключения (`browser_mismatch` с командой исходной
цели в `next_action`). Другим экземпляром того же расширения (другой профиль,
переустановка) — при подключении, без единой команды браузеру. Пакет при этом
приостанавливается, а элементы не помечаются неудачными. Существующий пакет версии 3
без `browser` не хранит исходную цель; для него можно указать её явно при resume.
Пакет версии 2 из адаптера до выбора браузера продолжается только целью `brave` и при
первом подключении получает привязку. Незавершённая загрузка другого экземпляра новой сессией не
«усыновляется»: операции хранятся в расширении своего профиля. Состояние версии 1, сохранённое до появления транспорта,
читается без миграции и всегда означает CDP. Его ревизии сохраняются в версии 1.
Resume другим транспортом отвергается до запуска браузера с кодом
`transport_mismatch` и командой исходного транспорта в `next_action`. Поэтому пакет CDP
не продолжится через Brave и наоборот. `forvo batch-status` и `forvo batch-cancel`
одинаковы для обоих транспортов, работают без браузера и показывают
`effective_transport`.

Остановка исполнителя Brave не бросает операцию посреди загрузки. Ctrl+C или
`batch-cancel` передаются сессии, та отменяет и стирает собственную незавершённую загрузку
и только потом завершается. Если освобождение не уложилось в 30 секунд, операция
освобождается при следующем подключении, а в паузе отмечается `recovery_required`.
Проверенные байты, полученные до остановки, всё равно фиксируются в контрольной точке. Порядок
прежний: байты и сведения о происхождении сначала попадают в неизменяемый blob, затем импортируются
с CAS. После сбоя импорта или падения между импортом и итоговым состоянием продолжение
берёт те же сохранённые байты, без браузера. Падение во время загрузки оставляет
элемент без контрольной точки, и продолжение скачивает его заново. Импортированные элементы не
скачиваются повторно. По завершении CLI закрывает только соединение bridge. Brave
и вкладки пользователя не закрываются. Собственная вкладка закрывается только по
`--close-tab`.

## Обновление из выпусков

Кроме встроенной в CLI версии адаптер обновляется из канала выпусков проекта:
GitHub Releases с тегами `forvo-extension-v<версия>` (не общий `/releases/latest`
репозитория). Устройство канала, подписи и процедура сопровождающего —
[forvo-extension-release.md](forvo-extension-release.md).

```bash
pronunciation-assets forvo browser [--target <имя>] update-check            # доступная версия, без установки
pronunciation-assets forvo browser [--target <имя>] update                  # наибольшая опубликованная версия
pronunciation-assets forvo browser [--target <имя>] update --version 0.4.0  # конкретная версия
pronunciation-assets forvo browser [--target <имя>] update --from-dir <каталог> # офлайн: скачанный выпуск
```

Порядок `update`:

1. **Проверка до записи.** Метаданные, подпись и ZIP скачиваются в память (пределы
   размера) или читаются из `--from-dir` и проверяются целиком: подпись Ed25519
   закреплённым ключом, канал, тег запрошенной версии, репозиторий, протокол bridge,
   SHA-256 и размер архива, безопасное извлечение (без `..`, абсолютных путей,
   повторов, ссылок, каталогов, исполняемых прав, сжатия и шифрования, не больше
   32 файлов и 4 МиБ), точный состав и SHA каждого файла, наличие `forvo_page.js`,
   допустимый manifest (имя, только разрешения этого CLI, без `key` и `update_url`).
   Скачанный код не исполняется.
2. **Блокировка цели.** Порт bridge — общий замок команд цели: при идущем `fetch`,
   пакете, `setup`, `doctor` или втором `update` — отказ `adapter_busy` без изменений.
3. **Сравнение версий.** Та же версия — `up_to_date` (no-op; `--reinstall` повторяет
   установку, если файлы отличаются от выпуска). Старшая установленная — отказ
   `downgrade_refused`. Первичная установка этим путём невозможна
   (`extension_files_missing`): её выполняют `setup` и ручная «Загрузить распакованное».
4. **Свободное расширение.** Расширение должно подключиться и пройти ту же проверку
   ID, экземпляра и секрета. Незавершённая собственная загрузка — отказ
   `update_deferred_operation_pending`: файлы не меняются, `reload` не вызывается.
5. **Транзакция в прежнем каталоге.** Каталог установки не переименовывается: от строки
   его пути зависит ID. Журнал `.toolkit-install-journal.json`, полные копии новых
   (`*.update-new`) и прежних (`*.update-old`) файлов создаются до первой замены, поэтому
   нехватка места проявляется до изменения рабочих файлов. Затем атомарные `rename`
   (`manifest.json` последним) и сверка SHA каждого файла. `pairing.json` пишется из
   прежних порта и секрета, `state.json` не меняется.
6. **Перезагрузка и подтверждение.** `chrome.runtime.reload()` собственного расширения,
   затем подключение того же ID и экземпляра с новой версией — `status=updated`. Если
   браузер перезагрузил прежнюю версию — `extension_reload_ineffective`, если
   подключение не подтвердилось — `extension_reload_unconfirmed`; в обоих случаях
   `files_installed=true` и действие «Обновить» на странице расширений. Полное
   обновление без подтверждения не сообщается.

**Сбой и откат.** Любая команда цели, заняв порт, сначала восстанавливает прерванную
установку по журналу: подготовка отбрасывается, начатая замена откатывается из
`*.update-old` со сверкой прежних SHA, зафиксированная — дочищается. Повтор после
обрыва сети, ошибки записи, нехватки места, `SIGKILL` или сбоя питания безопасен.
Если прежние копии подменены и откат не доказуем — `install_recovery_failed` без
изменений; восстановите каталог `setup` или `update --from-dir`. Файлы каталога,
которых нет в пакете, не трогаются.

**Встроенная версия и выпуск.** CLI несёт встроенную версию адаптера: она нужна для
первичной установки и офлайн-восстановления. Установленный выпуск новее встроенной
`setup`, `doctor --reload` и автоматическая синхронизация не откатывают; `doctor`
сверяет подключённое расширение с версией в каталоге цели (`installed_version`).
Понижение возможно только ручной переустановкой.

**Офлайн.** Без сети `update` отказывает `update_source_unavailable` с действием
`--from-dir`; получение MP3 от сети GitHub не зависит. Каталог `--from-dir` содержит
файлы выпуска как в GitHub Release: `forvo-extension-release.json`,
`forvo-extension-release.json.sig` и `forvo-extension-<версия>.zip`.

**Автоматическая проверка.** После успешного `fetch` и пакета адаптера CLI не чаще раза
в неделю проверяет доступную версию (не дольше 3 с, после получения MP3) и сообщает
`adapter_update` с действием; установку сам не выполняет. Результат кэшируется в
`updates/check.json` каталога состояния; `forvo.update_check = "off"` выключает проверку.

**Корень доверия.** Пока в CLI не закреплён ни один ключ подписи, `update` и
`update-check` отказывают `release_trust_root_missing` (`BLOCKED`) — это внешний шаг
сопровождающего, а не неисправность. `--trusted-public-key <файл>` (hex открытого
ключа Ed25519) заменяет встроенный корень для собственной сборки или изолированной
проверки; источник и канал при этом прежние.

## Диагностика

Все этапы пишутся в журнал NDJSON общего `RunLogGuard` (подкаталог `logs/` каталога состояния)
с одним `operation_id`: `brave_download_activated`, `brave_download_state`,
`brave_download_complete`, `brave_download_validated`, `brave_download_failed`,
`brave_download_reconnect`, `brave_download_released`, `brave_operation_recovery`.
Это идентификатор, ID загрузки, имя файла без каталога, размеры, SHA, коды и
длительности. Cookies, заголовки, HTML страницы, секрет сопряжения, URL
пользовательских вкладок и полные пути загрузок не записываются. Расширение
пишет в консоль service worker только `operation_id` и событие.

## Команды

```bash
# Выбор и настройка браузера
```

`--store` задаёт хранилище, как у остальных команд, а `--state-dir` задаёт каталог
сопряжения (у `forvo brave` — до подкоманды). План пакета — тот же строгий JSON, что у CDP. Результат
`fetch` содержит `asset`, `acquisition` (`ForvoEvidence`) и `browser`. В `browser`
записаны цель, браузер, ID и версия расширения, выполненное обновление, операции загрузок с освобождением, восстановленная
операция прошлого запуска и `user_tabs_untouched`. Журнал `fetch` лежит в подкаталоге
`logs/` каталога состояния, журнал пакета — в runtime пакета (`result.diagnostic_log`).
Коды завершения общие: 0 — успех, 3 — пауза из-за блокера или отказ,
130 — Ctrl+C или `cancelled`.

В WSL `setup` кладёт расширение Windows-браузера в
`%LOCALAPPDATA%\AnkiDeckToolkit\forvo-<цель>-adapter` и выводит Windows-путь. В
обычном Linux (и для Linux-браузера в WSL) — в
`$XDG_DATA_HOME/anki-deck-toolkit/forvo-<цель>-adapter`. Каталог цели `brave` совпадает
с прежним `forvo-brave-adapter`, поэтому ID установленного расширения сохраняется.

`doctor` и `smoke` возвращают шаги `PASS`/`FAIL`/`BLOCKED`/`NOT_TESTED`/`INTERRUPTED`
с доказательствами. Внешний блокер (Challenge, вход, 429) даёт `BLOCKED` без повторов.
Журнал NDJSON общего `RunLogGuard` лежит в подкаталоге `logs/` каталога состояния,
проверенный MP3 `smoke` — в `evidence/` (0600). `doctor`/`smoke` хранилище ресурсов и
колоды не меняют.

Шаги `doctor`, кроме транспорта и задержки:

| Шаг | Что проверяет |
|---|---|
| `installation` | исполняемый файл цели существует и это тот же браузер (PE/`--version`); без сохранённого пути — обнаружение; не найдено — `NOT_TESTED` |
| `extension_files` | файлы каталога цели и их отличие от версии CLI до подключения |
| `wsl_networking` | режим сети WSL2 (`wslinfo`) и факт подключения браузера Windows к bridge в WSL |
| `extension_connected` | ID из каталога цели, закреплённый экземпляр, число отклонённых подключений по причинам |
| `extension_version` | версия подключённого расширения совпадает с установленной в каталоге цели (встроенной в CLI или более новой из выпуска) после автоматического обновления |
| `browser_identity` | бренды `navigator.userAgentData`, сообщённые самим расширением, против браузера цели. Vivaldi представляется брендом «Google Chrome» и по нему неотличим — `NOT_TESTED`, а не `PASS` |
| `browser_capabilities` | MV3 service worker, `chrome.downloads` (с `search`), неблокирующий `webRequest`, `tabs`, `tabGroups`, `scripting`, `storage.local/session`, `alarms`, WebSocket + WebCrypto HMAC и версия Chromium ≥ `minimum_chrome_version`. Недостаток — `BLOCKED browser_capability_missing`/`browser_version_unsupported` |
| `download_settings` | всегда `NOT_TESTED`: настройку «Спрашивать, куда сохранять» расширение не читает; фактическое поведение показывает `smoke` (`save_as_required` со страницей настроек браузера) |

Сведения о браузере расширение берёт только о себе: бренды `userAgentData` и наличие
API. Разрешений на управление другими расширениями, чтение всех сайтов, профилей или
истории у него нет (`tabs`, `management`, `<all_urls>` и `history` отсутствуют).

**WSL2.** Bridge всегда слушает `127.0.0.1` в WSL. В режиме `mirrored` браузер Windows
достигает его напрямую. В режиме NAT — только через localhost forwarding WSL
(`localhostForwarding=true`, по умолчанию). Программа не расширяет слушатель, не
меняет `.wslconfig`, firewall и portproxy. Если браузер Windows не подключился, `doctor`
показывает режим и безопасные варианты: включить `networkingMode=mirrored` или
localhost forwarding самостоятельно.

## Изолированный E2E

Поведение расширения, bridge и Rust-контрактов проверяет явный набор
`cargo run -p anki-e2e -- browser [--chrome <путь>]`. Он запускает настоящий браузер
(Chromium, Chrome for Testing, Google Chrome, Edge или Vivaldi) с временным профилем и
этим же расширением, а локальный HTTPS fixture выдаёт себя за `forvo.com` только в
тестовом профиле. Набор не требует живого Forvo, авторизации и профиля пользователя.
Его контракт описан в [документации стенда](../anki-e2e/README.md#браузерный-набор-forvo-brave).
Живая проверка в основном браузере пользователя остаётся отдельной ручной проверкой по
разрешению пользователя.

Явный `--close-tab` возвращает ошибку при неуспешном закрытии. Для одиночного
`fetch` уже проверенный MP3 импортируется и при ошибке закрытия: `error.details.asset`
и `acquisition` сохраняют результат; повторное скачивание для очистки не нужно.
`browser.recovery_required` отличает полученные байты от полного освобождения
операции. При отказе `download_release` пакет сохраняет байты до паузы, а
`paused.recovery_required` остаётся `true` после повторного чтения состояния.
При продолжении освобождается только связанная собственная загрузка; сохранённый
элемент импортируется без повторного скачивания. Старые состояния без этого поля
читаются со значением `false`.

Real-Site всегда завершает команды отдельной попыткой `close`, в том числе после
ошибки или прерывания. `PASS` требует подтверждений `own_tab_absent` и
`own_group_absent`. Группа без доказательства владения остаётся нетронутой,
но препятствует успешному итогу очистки; исходный сбой и результат очистки
сохраняются в JSON и Markdown.

Для нового подтверждения очистки обновите установленный адаптер штатным
`forvo browser setup --browser <браузер> [--target <имя>]` (для Brave также
`forvo brave setup`), затем выполните
`forvo browser [--target <имя>] doctor --reload`. Старый ответ
`close` без подтверждений отсутствия вкладки и группы даёт `cleanup_incomplete`.
