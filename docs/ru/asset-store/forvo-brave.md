# Forvo через обычный Brave: адаптер-расширение

`pronunciation-assets forvo brave` работает с Forvo через обычный авторизованный
Brave пользователя (или другой Chromium с MV3), без отдельного профиля,
`--remote-debugging-port`, Browser MCP и экспорта cookies. Отдельный профиль
Cloudflare отклонял (`403`, `cf-mitigated: challenge`); основной профиль пользователя
проходит. Состояние на сегодня: прототип одной записи. Пакетное получение и импорт
в `AssetStore` по-прежнему идут через [CDP-провайдер](forvo.md).

## Архитектура

- MV3-расширение (`tools/asset-store/src/forvo/brave/extension/`) — тонкий транспорт.
  Оно подключается WebSocket-клиентом к локальному bridge `ws://127.0.0.1:47613/forvo-adapter/v1`
  и выполняет фиксированный набор команд: `ping`, `tab_status`, `open`, `navigate`,
  `auth`, `dom`, `download`, `fetch_observed`, `downloads_api`, `download_cleanup`,
  `snapshot`, `close`, `reload`. Произвольного кода, `eval`, `debugger`, `cookies`,
  `tabs` и `webRequest` нет. Права: `https://forvo.com/*` и `http://127.0.0.1/*`.
- Разметку страницы читают те же `forvo/dom.js` и `forvo/auth.js`, что и CDP-провайдер.
  `setup` собирает из них `forvo_page.js`; второй реализации DOM-логики нет.
- Rust принимает все решения: навигацию, проверку входа, рейтинг и выбор кандидата
  (`Candidate::validate`, `rank`), проверку адреса загрузки (`matches_download`),
  SHA-256 и `probe_mp3`.

## Сопряжение и безопасность

`setup` создаёт 32-байтный секрет и записывает его в `pairing.json` каталога
расширения и в приватный `state.json` (0600) каталога состояния
(`$XDG_CONFIG_HOME/anki-deck-toolkit/forvo-brave/`, `--state-dir`). Единственный акт
доверия — установка расширения из этого каталога. Bridge:

- слушает только `127.0.0.1` (не `0.0.0.0`); `doctor` проверяет недоступность порта
  по нелокальным адресам;
- до upgrade проверяет путь, `Host` и `Origin: chrome-extension://<id>`; после первого
  сопряжения ID расширения закрепляется (смена каталога или ID — `setup --rotate-secret`);
- проводит взаимную проверку HMAC-SHA256 по одноразовым nonce: расширение не
  исполняет команды bridge, не знающего секрета, а bridge отвергает клиента без секрета;
- ограничивает размер сообщений и принимает только известные типы и операции.

Секрет, cookies, HTML и заголовки не попадают в stdout, журналы и отчёты. Bridge
не делает исходящих HTTP-запросов, поэтому `HTTP_PROXY`/`HTTPS_PROXY` в WSL на него
не влияют. Chromium не проксирует `127.0.0.1`.

## Вкладка и жизненный цикл

Расширение создаёт одну неактивную вкладку в свёрнутой группе `Anki Deck Toolkit`
и запоминает её ID. После `chrome.runtime.onStartup` (перезапуска браузера) состояние
сбрасывается, чтобы не «усыновить» чужую вкладку с тем же ID. Если пользователь закрыл
вкладку, следующая команда создаёт новую. Пользовательские вкладки не читаются: снимок
изоляции содержит только ID, окна, группы и порядок.

Service worker держит соединение keepalive-сообщениями каждые 20 секунд. После
разрыва он делает 5 быстрых попыток, дальше подключается по `chrome.alarms` раз
в 30 секунд. Поэтому первое подключение после простоя может занять до 30 секунд.
Ctrl+C, отключение и перезапуск bridge закрывают только соединение: Brave,
вкладки и настройки загрузок не меняются.

## Загрузка MP3 и настройка «Спрашивать, куда сохранять»

В Brave эта настройка включена по умолчанию. Live-проверка показала:

- `chrome.downloads.download({saveAs:false})` при включённой настройке всё равно
  открывает «Сохранить как». `chrome.downloads.cancel` такой диалог не закрывает,
  и он не закрывается при закрытии вкладки. Поэтому путь через файл в Downloads
  без ручного действия заблокирован, а проверка доступна только по явному
  `smoke --probe-downloads-api`.
- Подсказка имени в `onDeterminingFilename` диалог не отключает.

Рабочий путь: Rust выбирает запись, расширение повторно проверяет строку и нажимает
обычную кнопку Download этой строки. Затем в `onDeterminingFilename` оно отменяет
загрузку сайта до этапа подтверждения: диалог не открывается, а элемент удаляется
из истории. Rust сверяет наблюдённый URL с контрактом
`/download/mp3/<слово>/ja/<id>`. После этого расширение по одноразовому токену читает
**именно этот** адрес через `fetch` в собственной вкладке `forvo.com` (тот же origin
и сессия) и передаёт байты в Rust. Адрес от Rust расширение не принимает.

Перехватчик действует только для загрузок, связанных с forvo.com. Он включён на
время операции и ещё 180 секунд после неё: запоздавшая загрузка сайта иначе
открыла бы диалог. Остальные загрузки сразу получают пустой `suggest()` и идут
обычным путём.

## Команды

```bash
pronunciation-assets forvo brave setup                 # каталог расширения и сопряжение
pronunciation-assets forvo brave doctor [--forvo] [--reconnect] [--reload]
pronunciation-assets forvo brave smoke --surface 元気 --reading げんき [--close-tab] [--probe-downloads-api]
pronunciation-assets forvo brave close
```

В WSL `setup` кладёт расширение в `%LOCALAPPDATA%\AnkiDeckToolkit\forvo-brave-adapter`
и выводит Windows-путь, в обычном Linux — в `$XDG_DATA_HOME/anki-deck-toolkit/forvo-brave-adapter`.
Единственное ручное действие: `brave://extensions` → «Режим разработчика» →
«Загрузить распакованное» → этот каталог. Повторный `setup` обновляет код, а
`doctor --reload` перезагружает расширение командой без участия пользователя.

`doctor` и `smoke` возвращают шаги `PASS`/`FAIL`/`BLOCKED`/`NOT_TESTED` с
доказательствами. Внешний блокер (Challenge, вход, 429) даёт `BLOCKED` без повторов.
Журнал NDJSON общего `RunLogGuard` лежит в `logs/` каталога состояния,
проверенный MP3 `smoke` — в `evidence/` (0600). Хранилище ресурсов и колоды не
меняются. Режим WSL2 NAT и нативный Linux Brave live не проверялись.
