# Forvo Web: японские произношения

`pronunciation-assets forvo` получает оригинальные MP3 через обычные кнопки сайта.
Транспортов два: собственный постоянный профиль Chromium через CDP (этот документ) и
MV3-адаптер в обычном браузере пользователя ([forvo-brave.md](forvo-brave.md)).
Предметная логика у них одна: кандидаты и ранжирование, переход к следующей записи,
проверка MP3, `ForvoEvidence`, staging, сохранение оригинала, checkpoint и resume. Forvo API,
скрытые аудио endpoints, ASR, DSP и автоматическое подтверждение чтения не
используются. Для CDP нужны Linux/WSLg, Chromium и зависимости
[технической проверки MP3](pronunciation.md).

## Общий путь: выбор транспорта

Общий пользовательский путь — `forvo fetch`, `forvo batch-start|batch-resume` —
выбирает транспорт по стратегии; явные `forvo brave …` и `forvo browser …` всегда
используют адаптер и стратегию не читают.

| Стратегия | Поведение |
|---|---|
| `chromium_first` (по умолчанию) | сначала собственный Chromium/CDP; переход к уже настроенному адаптеру — только при доказанном отказе транспорта CDP до опасных побочных эффектов |
| `extension_only` | только установленное и сопряжённое расширение выбранной цели; собственный Chromium не запускается даже для проверки (`login`, `check`, `candidates` отказывают `cdp_disabled_by_mode`) |

Стратегия и цель задаются в личном файле
`$XDG_CONFIG_HOME/anki-deck-toolkit/config.toml` (иначе `~/.config/…`); путь
заменяют `ANKI_DECK_TOOLKIT_CONFIG` и явный `forvo --config <файл>`. Это общая
пользовательская конфигурация инструментов, не входящая в репозиторий: путей
профилей и секретов в ней нет, сопряжение хранит каталог состояния адаптера.
Конфигурация inference — отдельно ([README](README.md#локальный-inference-llamacpp-и-ollama)).

```toml
schema_version = 1          # необязательно

[forvo]
mode = "chromium_first"     # или "extension_only"
browser_target = "brave"    # имя настроенной цели адаптера; без него — цель по умолчанию
update_check = "weekly"     # редкая проверка новой версии адаптера; "off" — выключить
```

`update_check` берётся из итоговой конфигурации, в том числе при явном
`forvo --config <файл>`. Автоматическая проверка выполняется только после
успешного `fetch`, `batch-start` или `batch-resume` через адаптер; после ошибки
или работы только через CDP сетевого запроса нет. Значение `off` отключает её на
всех этих путях.

Разбор строгий: неизвестный раздел, ключ или значение — ошибка `config_invalid` с
названием ключа; отсутствующий явно названный файл — `config_unreadable`.
Отсутствие файла по умолчанию — обычное состояние. Явные флаги общего пути важнее
файла: `forvo --mode extension_only`, `--browser-target <цель>`,
`--adapter-state-dir <каталог>` (как `--state-dir` у `forvo browser`).
`forvo config` показывает итог, источник каждого значения (`cli`, `file`,
`default`) и настроенные цели. Без `browser_target` действует прежняя модель
`default_target`/единственной цели; неоднозначность — `target_ambiguous`, а не угадывание.

**Когда допустим переход `chromium_first` → адаптер.** Только при backend failure CDP:

- собственный Chromium не запустился (`browser_recovery_required`, `gui_unavailable`)
  или его профиль занят другим процессом (`browser_profile_busy`) — в браузере и на
  сайте ещё ничего не сделано;
- для одиночного `fetch` также: профиль CDP не авторизован (`login_required`,
  `session_expired`), а загрузка записи ещё не начиналась;
- уборка собственного Chromium завершена, команда не прервана, адаптер настроен.

Предметная ошибка не даёт права на переход: `rate_limited`, `access_denied`,
`challenge_required`, `word_not_found`, `candidates_exhausted`, ошибки аудио,
проверки MP3 и диска, чужая загрузка, `browser_profile_not_owned`,
`browser_cleanup_failed`, прерывание. Такая ошибка возвращается как есть.
Решение и причина всегда в `transport_decision` результата или ошибки: `mode`,
`mode_source`, `attempts` (транспорт, этап, код), `fallback` (`used`, `reason`,
`failure_kind=backend|domain_or_unsafe`, `refused_because`, `adapter_unavailable`),
`cdp_attempted`. Искусственных задержек нет: стратегии различаются порядком и
допустимостью транспорта, а не скоростью.

**Новый пакет** выбирает транспорт до первой долговечной записи. `chromium_first`
сначала запускает собственный Chromium; при успехе создаётся пакет `cdp_chromium`, и
он исполняется уже запущенной сессией. Если запуск не удался (backend failure) и
адаптер настроен, создаётся пакет `brave_extension` с целью, сохранённой до первого
подключения (`schema_version=4`). Иначе — прежнее поведение: пакет CDP,
приостановленный отказом. `extension_only` сразу создаёт пакет адаптера; без
настроенной цели пакет не создаётся. Переход внутри уже созданного пакета невозможен.

**`forvo batch-resume`** продолжает пакет сохранённым транспортом и привязкой, а не
текущей стратегией (`transport_decision.source=batch_binding`): пакет адаптера —
своей целью и экземпляром расширения, пакет CDP — собственным Chromium. Смена
конфигурации пакет не мигрирует. В режиме `extension_only` пакет CDP не
продолжается и Chromium не запускается (`transport_disabled_by_mode`, действие —
`forvo --mode chromium_first batch-resume …`). Явный `--browser-target`, не
совпадающий с целью пакета, — `browser_mismatch`. Явные `forvo brave|browser
batch-resume` для пакета CDP по-прежнему отказывают `transport_mismatch`.

Совместимость: без файла конфигурации общий путь начинает с CDP. Если настроен
адаптер, новый переход к нему возможен при отказе запуска Chromium, а для одиночного
`fetch` — также при отсутствии авторизации до начала загрузки; выбор виден в
`transport_decision`. После успешной операции через адаптер по умолчанию возможна
редкая сетевая проверка обновления расширения (`forvo.update_check = "off"` её
отключает). Общий `batch-resume` пакета адаптера раньше отказывал
`transport_mismatch`, теперь продолжает его сохранённой привязкой.

## Вход и профиль

```bash
cargo run --locked --bin pronunciation-assets -- forvo login
cargo run --locked --bin pronunciation-assets -- forvo check
```

Пользователь сам проходит Cloudflare и вводит пароль на сайте. CLI паролей не
принимает. `login` ждёт до 300 секунд (`--timeout-seconds`, максимум 1800).
Для `login` нужен GUI; `check`, `candidates`, `fetch` и пакетное получение
работают в фоновом Chromium без дисплея, используя тот же постоянный профиль.
При запросе входа или проверке сайта при доступном дисплее фоновый браузер
закрывается, открывается окно ручного взаимодействия и после подтверждения входа
работа продолжается в новом фоновом процессе. Без дисплея пакет приостанавливается:
выполните `forvo login` в среде с GUI и продолжите `batch-resume`.
Авторизация подтверждается меню аккаунта с выходом, а не наличием cookie.
Общие ссылки `/login/` существуют и на авторизованных страницах.

Профиль по умолчанию — `.codex/local/forvo-profile/`, отдельно от аудиокорпуса.
`forvo --profile <абсолютный-путь>` выбирает другой отдельный приватный каталог.
Профиль и фактический корень `--store` (включая значение по умолчанию) не могут
совпадать или содержать друг друга. До создания каталогов проверяются существующие
предки и их алиасы; пересечение с защищённым `decks/**` также запрещено.
Существующий обычный профиль Chrome не принимается: проверяются маркер владельца,
UID, права 0700 и эксклюзивная блокировка. Symlink и `..` запрещены. Один профиль
используется одним процессом. При закрытии сохраняется профиль, но останавливается
принадлежащая группа процессов и удаляются временные ресурсы. Режим Yarxi/JPDB
остаётся headless/incognito с удаляемыми профилями.

Для восстановления повторите `forvo login`; пакеты и обработанные слова останутся.
Если проверяется только определённая страница, `forvo login --surface こいつ`
открывает именно её и ждёт ручного прохождения проверки с подтверждением входа.
Блокировки Chromium не удаляются вслепую: сначала проверьте отсутствие своего
браузера. Для выхода используйте обычный выход из аккаунта в окне сайта. Для полной
очистки закройте использующие профиль команды и удалите только выбранный собственный
каталог профиля. CLI автоматически его не удаляет. Корпус и пакеты при этом не
удаляются. Cookies, токены, пароли и полный HTML страниц в результаты не попадают.

## Слово и кандидаты

```bash
pronunciation-assets forvo candidates --surface 元気
pronunciation-assets forvo fetch --surface こいつ
```

Поиск на Forvo всегда идёт **только по написанию**: адрес — точная страница
`https://forvo.com/word/<surface>/`, а чтение ни в запрос, ни в адрес не входит
(`生_せい`, `生（せい）`, `生 なま` не формируются). Адаптеры CDP и расширения
получают от общего пути только `surface`. Чтение на стадии Forvo отсутствует;
`--reading` и `--replace-expected-sha256` отвергаются парсером.

`candidates` не скачивает файлы и не открывает хранилище. Адаптер проверяет URL
точного слова, японский контейнер, его основной список и ссылку языка в заголовке.
Другие языки, отдельные статьи Phrases и блок «Related words and phrases»
(например `生（セイ）`, `生きる` на странице `生`) исключены: это другие записи и
написания, а кнопка Download строки обязана нести точное написание страницы. `View all` раскрывается обычной
кнопкой. Слово, язык и ID кнопки сверяются со строкой; один ID или `#ja` не доказывает
принадлежность языку. Неизвестная структура даёт `dom_changed`.

Поля кандидата: устойчивый ID, публичный username, votes (включая 0 и отрицательные),
gender, country и доступность Download. Недоступные сведения имеют `null`. Пол и
страна разбираются только из реально присутствующей английской формы страницы
`forvo.com`; неизвестные формы не угадываются. Порядок: известные голоса по убыванию;
при равенстве женский голос; далее Japan; далее числовой ID по возрастанию.
Мужские голоса остаются кандидатами. `ranking_policy` версионирует порядок попыток,
который не доказывает правильного чтения.

`fetch` нажимает обычную кнопку выбранной записи. Слушатели CDP устанавливаются
до клика. Принимается загрузка из своей страницы/её новой вкладки с полным адресом
кнопки: точное слово, `ja` и ID. Сокращённого адреса недостаточно. `allowAndName`
задаёт имя по GUID, поэтому неожиданный `suggestedFilename` и отсутствующий
`filePath` не меняют читаемый путь. Нужны событие `completed`, согласованный размер,
обычный GUID-файл без symlink и полный технический MP3-проверяющий путь. HTML,
отмена и `.crdownload` успехом не считаются. Таймаут попытки — 120 секунд.
Staging принадлежит сессии до доказанной остановки Chromium, включая Ctrl+C.
Перед следующей попыткой браузер закрывается целиком, а затем открывается заново
с тем же профилем: предыдущая загрузка не удерживается весь длинный пакет.
При неподтверждённой остановке повторный запуск блокируется до завершения процесса;
оставшееся временное дерево удаляет штатная проверка осиротевших запусков.

Ошибка отдельной записи (включая повреждённый MP3) ведёт к следующему диктору.
Отказ создания staging, подписки CDP, управления загрузками, доступа к завершённому
файлу или его чтения приостанавливает пакет с исходным кодом и незавершённым
элементом. Исправьте окружение и выполните `batch-resume`; другие дикторы при таком
отказе не перебираются. Неизвестная ошибка также сохраняет свой код.
Блокировка сессии приостанавливает получение целиком. При 429/5xx на открытии слова — максимум три обращения с backoff
1 и 2 секунды. Между успешными операциями искусственных пауз нет. Один профиль
обрабатывает загрузки последовательно для однозначной корреляции.

Forvo может отдельно проверить Download после успешного входа. Пройдите проверку
вручную; если она завершена, но остался прежний экран, допустимо обычное ручное
обновление страницы. CLI не обходит защиту и не подставляет clearance cookies.
Если загрузка не завершилась, восстановите доступ и повторите команду/resume.
Успешный `check` подтверждает только вход; скачивание проверяется отдельно.

## Происхождение и доверие

Оригинальные проверенные MP3 сохраняются в управляемых blob существующего
`SafeBatchRuntime` внутри `<store>/.runtime/batches/` (по умолчанию
`.asset-store/pronunciation-audio/.runtime/batches/`). Свидетельство
`ForvoEvidence` схемы 1 связывает SHA с точной страницей, ID записи, доступными
метаданными диктора, ранжированным списком и фактическими попытками.
`fetch` возвращает `source.batch_id` и `source.source` (blob и evidence).
Результат доступен через `selection intake --from-forvo-batch <id>`. Повторный
`fetch` того же написания, транспорта и браузерной привязки использует сохранённый
оригинал без скачивания. Незавершённая очистка требует `batch-resume`.

Успех `acquired` означает наличие исходника без чтения. Он не создаёт
`pronunciation_audio`, лексическую пару, `Verified` или человеческое одобрение.
Готовые канонические ресурсы и их CAS остаются в прежнем домене; последующая
явная связь исходника с парой принадлежит [Selection](selection.md).

## Пакет

Строгий JSON-план: `schema_version=1`, 1–128 уникальных написаний:

```json
{"schema_version":1,"items":[{"surface":"学校"}]}
```

Неизвестные и повторные ключи отвергаются, включая `reading` и
`replace_expected_sha256`, даже со значением `null`. Написание нормализуется
в NFC и проходит существующую проверку допустимости страницы Forvo.

Для каждого написания получается список метаданных основного японского блока
точного слова. По существующему `RANKING` пробуется одна запись за раз;
после первой успешно скачанной и технически проверенной записи загрузки
останавливаются. Следующий кандидат пробуется только после доказанного отказа
записи (`rejects_candidate`). Блокер сайта, сессии или инфраструктуры сохраняет
реальный код, попытки и паузу. Исчерпание даёт `candidates_exhausted`.
Полного сбора и альтернативного режима выбора нет.

```bash
pronunciation-assets forvo batch-start --batch-id jp-audio --plan plan.json
pronunciation-assets forvo batch-status --batch-id jp-audio
pronunciation-assets forvo batch-resume --batch-id jp-audio
pronunciation-assets forvo batch-cancel --batch-id jp-audio
```

`--max-items` ограничивает число обработанных элементов; 0 только сохраняет/проверяет
пакет. Это состояние `SafeBatchRuntime` того же хранилища, без второй базы статусов.
На время сетевого ожидания блокировка состояния снимается, а отдельный execution
lease сохраняет единственного исполнителя. `status`/`cancel` работают без Chromium;
отмена проверяется во время ожидания. Отменённый пакет не возобновляется; для
временной остановки используйте Ctrl+C.

Проверенные байты и provenance фиксируются как неизменяемый blob. После
checkpoint возобновление использует сохранённые байты без загрузки; повторная
техническая проверка сохранённого MP3 не требует браузера. Ошибка инструментов
проверки приостанавливает пакет; после ремонта используются те же байты.
Отмена и ошибка очистки сохраняют уже полученный оригинал. Неосвобождённая
операция требует штатного восстановления перед продолжением.

Новые пакеты имеют `schema_version=5`; транспорт, цель и браузерная привязка
сохраняют прежние правила. `batch-status` и `batch-cancel` показывают
`effective_transport`. Версии состояния 1–4, свидетельства схем 1–2 и прежние
канонические ресурсы читаются без переписывания. Исторические пакеты доступны
для status/cancel и Selection со всеми сохранёнными blob и provenance.
Их `batch-resume` явно отклоняется с `legacy_forvo_batch` до запуска браузера:
создайте новый план только с `surface`. Старый полный сбор не возобновляется.

## Диагностика и проверки

Общий JSON-конверт содержит `schema_version`, `outcome` и `result`/`error`.
`outcome=paused` возвращает сохранённый пакет: exit 3 для блокера, 130 для Ctrl+C.
Если выполнявшийся пакет отменён через `batch-cancel`, его исполнитель возвращает
`outcome=cancelled` и exit 130; сама команда отмены сообщает сохранённое состояние.
Обычный успех — 0; ошибки целостности/ввода-вывода используют общие коды CLI.
Предметный код — `error.details.code`, `result.paused.code` или
`items[].outcome.code`. Диагностика содержит следующее действие.
Каждый `batch-start`/`batch-resume` создаёт отдельный JSONL-журнал общего runtime;
путь находится в `result.diagnostic_log` (при ошибке — в `error.details`).
JSON stdout не смешивается с диагностикой. Журнал содержит стадии и коды без
cookies, токенов, HTML и содержимого профиля.

Основные коды: `gui_unavailable`, `browser_profile_busy`, `browser_profile_not_owned`,
`challenge_required`, `login_required`, `session_expired`, `access_denied`,
`site_unavailable`, `page_unstable`, `dom_changed`, `page_identity_mismatch`,
`word_not_found`, `japanese_pronunciation_not_found`, `no_usable_candidates`,
`download_button_unavailable`, `download_button_obscured`, `download_mismatch`,
`download_aborted`, `download_timeout`, `download_staging_failed`,
`download_listener_failed`, `download_not_supported`, `download_file_missing`,
`download_read_failed`, `candidate_changed`, `candidate_disappeared`, `invalid_mp3`,
`technical_validation_failed`,
`rate_limited`, `browser_recovery_required`, `candidates_exhausted`, `transport_mismatch`,
`transport_disabled_by_mode`, `cdp_disabled_by_mode`, `config_invalid`, `config_unreadable`.

Offline-тесты адаптера требуют Chromium, но не обращаются к Forvo:

```bash
cargo test -p asset-store --lib --locked forvo::tests::browser_ -- --ignored
```

Они не заменяют живую приёмку: настоящий вход, несколько скачиваний и независимый
повторный запуск. Внешний блокер Cloudflare не считается успешным скачиванием.

## Ручное ожидание и восстановление одиночного получения

`fetch` обоих транспортов возвращает `source` (включая `batch_id`),
`acquisition` и `reused` (`true` при повторном использовании). При незавершённой
очистке команда завершается ошибкой: те же поля находятся в `error.details`
рядом с `recovery_required=true` и `next_action`. Сохранённый оригинал остаётся
доступен; переключение транспорта не обходит recovery, challenge или блокер.
`batch-cancel` сохраняет обязательство очистки. `batch-resume` отменённого
пакета с recovery подключается только для очистки и ничего не скачивает.

В ручном CDP-шаге CLI немедленно выдаёт NDJSON в stderr:
`event=human_interaction_required`, `session_id`, `action`, `wait_mode=deadline`,
`timeout_seconds`, `hint`, `next_action`. Автовосстановление ждёт 300 секунд,
`login` — выбранный `--timeout-seconds`. stdout сохраняет один итоговый JSON.
Событие `human_interaction_finished` завершает ожидание; истечение срока даёт
`human_wait=timed_out`, штатное прерывание — `interrupted` с очисткой собственного
браузера. При `SIGKILL` итоговый JSON не гарантируется. Авторизацию подтверждает
сам CLI, а не ответ пользователя. Протокол агента — в
[anki-live-testing](../../../.agents/skills/anki-live-testing/references/forvo-human-interaction.md).

Расширение при challenge/входе выдаёт то же событие с
`wait_mode=resume_required`, `timeout_seconds=null` и своим `next_action`:
текущая команда завершается отказом, дальнейший шаг требует явного повтора.
