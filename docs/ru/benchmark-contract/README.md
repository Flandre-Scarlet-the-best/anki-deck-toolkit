# Контракт измерений: `benchmark-contract`

**Русский** · [English](../../en/benchmark-contract/docs/ru/README.md) · [简体中文](../../zh-CN/benchmark-contract/docs/ru/README.md)

`benchmark-contract` — библиотека и CLI, которые загружают каталог сценариев
бенчмаркинга `benchmarks/`, проверяют декларации и результаты измерений,
импортируют экспорт Hyperfine 2.0 и отвечают, сопоставимы ли два результата.
Смысл полей, профилей, метрик и правила регистрации сценария —
[руководство по каталогу](../performance/benchmarks.md); общие правила
замеров — [методика](../performance/docs/ru/README.md).

Инструмент ничего не запускает и не измеряет: он читает TOML каталога,
манифесты Cargo и JSON результатов. Он не пишет файлов, не обращается к сети и
не трогает колоды, медиа, профили Anki, `decks/**` и `.asset-store/`. Серии
по каталогу выполняет [`benchmark-runner`](../benchmark-runner/docs/ru/README.md),
используя эту библиотеку.

## Команды

```bash
cargo run -p benchmark-contract -- validate
cargo run -p benchmark-contract -- list
cargo run -p benchmark-contract -- show anki-repo.validate
cargo run -p benchmark-contract -- preflight anki-e2e.full
cargo run -p benchmark-contract -- check-result result.json
cargo run -p benchmark-contract -- check-result --no-catalog result.json
cargo run -p benchmark-contract -- compare before.json after.json
cargo run -p benchmark-contract -- vocabulary
```

| Команда | Что делает |
|---|---|
| `validate` | загружает каталог и проверяет все декларации; печатает диагностику |
| `list` | сценарии: ID, ревизия, вид, статус, профили |
| `show <id>` | типизированная декларация так, как её понял загрузчик |
| `preflight <id>` | можно ли измерять сценарий здесь: ОС из `platforms`, `PATH`, cgroup v2, `perf_event_paranoid`; сеть и демон Docker не проверяются |
| `check-result <файл>…` | проверка результатов; по умолчанию и по декларации каталога |
| `compare <a> <b>` | сопоставимость двух корректных результатов одного сценария |
| `vocabulary` | реестр метрик, областей охвата, источников, единиц и пределов прогонов |

Глобальные параметры: `--catalog <каталог>` — каталог с `catalog.toml` (по
умолчанию `benchmarks/` ближайшего родителя текущего каталога); `--json` —
стабильный JSON вместо текста. Текстовая диагностика выводится в stderr.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | каталог или результаты корректны; `preflight` — платформа поддерживается и все проверенные зависимости доступны; `compare` — результаты сопоставимы |
| `1` | найдены ошибки контракта; `preflight` — платформа не поддерживается, зависимость отсутствует или ограничена; `compare` — результаты несопоставимы или некорректны |
| `2` | неверные аргументы командной строки |
| `3` | каталог не найден, файл не читается, сценарий с указанным ID не найден (`show`, `preflight`) или каталог некорректен для команды, которой нужен корректный каталог |

## Диагностика

Каждая запись содержит уровень (`error` или `warning`), стабильный машинный
код, файл относительно корня каталога или имя документа, ID сценария и путь
поля (`profile[1].prepare[0].program.name`, `runs[2].values.<ключ>`).
Предупреждения не делают каталог некорректным. Неподдерживаемая
`schema_version` — ошибка `unsupported_schema_version` до разбора остальных
полей.

## Библиотека

| Модуль | Назначение |
|---|---|
| `catalog` | обнаружение, загрузка и семантическая проверка каталога |
| `scenario` | типы деклараций и проверка формы с путём поля |
| `vocabulary` | закрытый словарь, реестр метрик, пределы прогонов |
| `result` | типы результата и его проверка, пересчёт агрегатов |
| `hyperfine` | разбор и импорт `--export-json` Hyperfine 2.0 |
| `comparability` | правила сопоставимости |
| `preflight` | проверка платформы и доступности зависимостей только чтением |

## Проверки

Тесты строят собственные каталоги из учебных фикстур `tests/fixtures/` и
проверяют также настоящий `benchmarks/`; Docker, Anki и Hyperfine им не нужны.
Они входят в `cargo test --workspace --locked`.
